# 数据服务 WBS（实施排期版）

## 1. 文档目的

本文档基于《[数据服务-需求规格书](/Volumes/osdisk/java_code/data-service/docs/research/common/数据服务-需求规格书.md)》和《[数据服务-架构与详细设计](/Volumes/osdisk/java_code/data-service/docs/research/common/数据服务-架构与详细设计.md)》整理形成，用于输出数据服务项目的实施排期版 WBS，作为项目排期、资源协调、里程碑跟踪、阶段验收和实施推进的直接依据。

本文档不替代需求文档、设计文档和详细任务拆解文档，实施排期版 WBS 主要回答以下问题：

- 项目按什么阶段推进
- 每个阶段的关键工作包、关键交付物和完成标志是什么
- 各阶段之间的前置依赖、并行关系和关键路径是什么
- 每个阶段进入下一阶段前必须满足哪些验收门禁

## 2. WBS 编制原则

- 以需求范围和详细设计为唯一依据，不新增范围外工作
- 按阶段实施，先第一阶段，后第二阶段；第一阶段验收完成后方可进入第二阶段
- 以阶段目标、关键交付物、依赖关系和验收门禁为主线组织正文
- 正文粒度以可排期的工作包为主，不以下钻四级任务作为正文主体
- 对前端、后端、测试、发布、权限审计、运维观测等工作统一纳入同一实施主线
- 第一阶段与第二阶段必须连续演进，不允许推翻式重构
- 设计与实施默认满足单机 4 核 CPU、16G 内存部署基线，并将资源保护纳入阶段门禁

## 3. 实施排期总览

### 3.1 一级 WBS

| WBS 编码 | 工作项 | 说明 |
| --- | --- | --- |
| 1 | 项目基础与公共支撑 | 覆盖环境、规范、基础框架、元数据、公共能力、权限审计与观测底座 |
| 2 | 第一阶段：基础数据服务能力建设 | 覆盖连接管理、服务配置、统一查询、批量查询、基础跨库、缓存、前端配置界面 |
| 3 | 第二阶段：联邦 SQL 平台能力建设 | 覆盖联邦 SQL 校验、优化、执行、方言适配、计划诊断、平台化能力 |
| 4 | 测试与质量保障 | 覆盖阶段测试、集成验证、性能验证、验收测试 |
| 5 | 发布与交付 | 覆盖发布准备、上线验证、培训、验收与移交 |

### 3.2 实施阶段总表

| 排期阶段 | 对应 WBS 范围 | 阶段目标 | 主要输出 | 完成标志 |
| --- | --- | --- | --- | --- |
| 准备期 | WBS 1 | 建立工程骨架、元数据底座、公共能力、权限审计与观测底座 | 工程骨架、迁移脚本、基础组件、权限与审计底座、观测底座 | 具备第一阶段实施所需的统一工程和基础支撑 |

| 第一阶段验收发布期 | WBS 4、WBS 5 中第一阶段相关内容 | 完成第一阶段测试、发布和验收闭环 | 第一阶段测试报告、发布记录、验收材料 | 第一阶段验收通过并形成可发布、可运行版本 |

## 4. 里程碑与阶段门禁

### 4.1 M1 基础工程与元数据底座完成

**入口条件：**

- 需求范围、阶段边界和设计基线已确认
- 第一阶段建设范围已冻结为基础数据服务能力

**里程碑输出：**

- 后端与前端工程骨架
- 元数据基础表结构与迁移脚本
- 通用后端基础组件与前端基础能力
- 权限审计底座与可观测性底座

**退出条件 / 门禁条件：**

- 能支撑连接管理、服务配置和统一查询能力继续开发
- 已明确单机 4 核 CPU、16G 内存资源基线及基础保护参数
- 基础权限模型、审计留痕模型和基础观测项已具备接入条件

**阻断项：**

- 元数据模型未稳定
- 工程骨架未打通，无法支撑后续模块并行开发
- 基础权限、审计或统一响应模型缺失

### 4.2 M2 第一阶段核心功能开发完成

**入口条件：**

- M1 已完成
- 连接管理、服务配置、统一查询相关基础依赖可用

**里程碑输出：**

- 数据源连接管理能力
- 数据服务配置与发布能力
- 统一查询 API、批量查询、基础跨库、查询缓存
- 第一阶段前端配置主流程
- 第一阶段权限审计与观测能力闭环

**退出条件 / 门禁条件：**

- 已发布服务可通过统一 API 正常调用
- 第一阶段主流程可从连接配置贯通至服务发布与调用
- 权限控制、审计留痕、常见异常反馈和基础资源保护均已接入

**阻断项：**

- 服务配置与发布链路未稳定
- 统一查询主流程未打通
- 权限审计或基础资源保护缺失

### 4.3 M3 第一阶段测试验收与发布完成

**入口条件：**

- M2 已完成
- 第一阶段测试环境、样例数据源与发布环境已就绪

**里程碑输出：**

- 第一阶段单元、集成、E2E、性能与验收测试报告
- 第一阶段发布记录、回归检查记录、回退验证记录
- 第一阶段验收结论

**退出条件 / 门禁条件：**

- 满足需求文档第一阶段验收口径
- 在 4 核 CPU、16G 内存单机环境下可稳定运行
- Oracle、MySQL、PostgreSQL 至少各完成一种连接与查询验证
- 至少完成一个跨数据库关联场景、一个批量查询场景和缓存命中场景
- 第一阶段验收通过后方可进入第二阶段

**阻断项：**

- 第一阶段核心验收场景未覆盖
- 存在阻断上线的安全、权限、稳定性或数据正确性问题
- 测试与发布未形成闭环

### 4.4 M4 第二阶段联邦 SQL 核心能力完成

**入口条件：**

- M3 已完成
- 第一阶段成果作为第二阶段底座继续沿用

**里程碑输出：**

- 联邦 SQL 元数据扩展
- 联邦 SQL 解析、校验、规划、优化能力
- 数据源能力模型、方言适配能力
- 联邦执行编排、动态过滤 / lookup 优化能力
- 联邦计划展示、诊断与平台前端能力

**退出条件 / 门禁条件：**

- 能为一个服务直接维护一条联邦 SQL
- 可完成联邦 SQL 校验、发布、执行与诊断展示
- 优化能力、方言适配和执行编排能力具备联调条件

**阻断项：**

- 联邦 SQL 校验链路不稳定
- 规划、优化、执行主链路未打通
- 数据源能力模型与方言适配缺失导致无法落地联邦执行

### 4.5 M5 第二阶段测试验收与最终交付完成

**入口条件：**

- M4 已完成
- 第二阶段联邦测试场景与验收环境已准备完成

**里程碑输出：**

- 第二阶段测试报告、性能与资源保护验证报告
- 第二阶段发布记录、培训材料、验收移交材料
- 最终验收结论

**退出条件 / 门禁条件：**

- 满足需求文档第二阶段验收口径
- 至少完成一个同构联邦 SQL 场景和一个异构联邦 SQL 场景
- 能体现 Join Reorder、Filter Pushdown、Project Pushdown
- 能体现复杂表达式、方言兼容、计划诊断和平台自助配置能力
- 在 4 核 CPU、16G 内存单机环境下具备受控并发、落盘缓冲和超预算快速失败能力

**阻断项：**

- 联邦 SQL 核心场景未通过验收
- 诊断、审计、权限和发布追溯能力不完整
- 单机资源保护验证不通过

## 5. 第一阶段实施排期

### 5.1 第一阶段目标与范围

第一阶段目标是建立统一数据服务基础框架，完成异构数据库接入、服务配置管理、统一查询 API、批量查询、缓存、基础跨库能力和前端配置界面，形成可发布、可调用、可测试、可验收的基础系统。

第一阶段边界说明：

- 第一阶段中的跨源能力以预定义、可控复杂度的组合查询为主
- 第一阶段不建设通用联邦 SQL 自助编辑平台
- 第一阶段不要求完整的联邦 SQL 优化器、方言兼容和计划诊断体系
- 第一阶段必须纳入权限、审计、观测、发布和验收门禁

### 5.2 基础准备流

**对应 WBS：** `1.1`、`1.2`、`1.3`、`1.4`、`1.5`、`1.6`

**主要工作包：**

- 建立后端与前端工程骨架
- 建立元数据基础表结构与迁移脚本
- 建立通用后端执行、校验、结果映射能力
- 建立通用前端页面骨架与请求封装
- 建立权限模型、审计模型和基础观测能力

**建议顺序：**

1. `1.1` 开发基础环境与工程骨架
2. `1.2` 元数据存储与基础表结构
3. `1.3` 通用后端基础能力
4. `1.4` 通用前端基础能力
5. `1.5` 权限与审计基础能力
6. `1.6` 运维与可观测性基础能力

**可并行项：**

- `1.3` 与 `1.4` 可在 `1.1`、`1.2` 之后并行推进
- `1.5`、`1.6` 可在公共模型稳定后并行接入

**前置依赖：**

- `1.1 -> 1.2 -> 1.3/1.4` 为准备期关键路径
- 权限审计与观测底座依赖工程骨架和基础模型稳定

**关键交付物：**

- 工程骨架
- 元数据迁移脚本
- 基础执行组件与公共前端框架
- 权限矩阵、审计表结构、基础监控与日志规范

**阶段完成标准：**

- 具备第一阶段功能开发所需的统一工程底座
- 元数据模型可支撑连接管理、服务配置和发布流程
- 权限、审计和观测能力具备接入条件

### 5.3 服务配置流

**对应 WBS：** `2.1`、`2.2`

**主要工作包：**

- 建设数据源连接管理与目标库配置能力
- 建设数据服务定义、参数、输出、缓存策略和发布管理能力
- 打通服务草稿、发布、停用的基本状态流转

**建议顺序：**

1. `2.1` 数据源连接管理
2. `2.2` 数据服务配置管理

**可并行项：**

- `2.1` 的前后端页面与接口可并行推进
- `2.2` 的服务编辑能力和配置子页面可并行推进

**前置依赖：**

- 依赖 `1.2` 元数据底座和 `1.3/1.4` 公共能力
- 发布链路依赖权限、审计和统一响应能力已接入

**关键交付物：**

- 数据源管理接口与页面
- 数据服务管理接口与页面
- 服务发布与停用能力

**阶段完成标准：**

- 支持连接新增、编辑、启停、测试和目标库配置
- 支持服务草稿保存、发布、停用
- 未发布服务不能被调用

### 5.4 查询能力流

**对应 WBS：** `2.3`、`2.4`、`2.5`、`2.6`

**主要工作包：**

- 建设第一阶段动态 SQL 执行能力和统一查询 API
- 建设批量查询能力
- 建设基础跨库关联能力
- 建设查询缓存能力

**建议顺序：**

1. `2.3` 第一阶段动态 SQL 执行能力
2. `2.4` 批量查询能力
3. `2.5` 第一阶段基础跨库关联能力
4. `2.6` 查询缓存能力

**可并行项：**

- `2.4`、`2.5`、`2.6` 可在 `2.3` 主链路稳定后并行推进
- 缓存能力可与跨库能力并行接入统一查询链路

**前置依赖：**

- 依赖 `2.1/2.2` 服务配置与发布链路稳定
- 依赖 `1.3` 执行器、参数校验、结果映射和资源保护默认值

**关键交付物：**

- 统一查询 API
- 批量查询接口
- 基础跨库关联逻辑
- 查询缓存组件与缓存策略支持

**阶段完成标准：**

- 已发布服务可通过统一 API 返回统一结果结构
- 至少完成一个批量查询场景和一个基础跨库关联场景
- 缓存命中、超时保护、结果集上限控制可验证

### 5.5 管控与支撑流

**对应 WBS：** `2.7`、`2.8`、`2.9`

**主要工作包：**

- 打通第一阶段前端配置主流程
- 实现第一阶段权限控制与审计查询能力
- 实现第一阶段监控、诊断摘要和发布后回归检查能力

**建议顺序：**

1. `2.7` 第一阶段前端配置界面
2. `2.8` 第一阶段权限与审计管理
3. `2.9` 第一阶段运维与观测能力

**可并行项：**

- `2.8`、`2.9` 可与 `2.3` 至 `2.7` 功能开发并行推进
- 审计查询页、监控页、错误摘要页可并行建设

**前置依赖：**

- 前端主流程依赖 `2.1`、`2.2`、`2.3` 至 `2.6` 核心接口基本稳定
- 权限审计依赖 `1.5` 基础能力；观测能力依赖 `1.6` 基础能力

**关键交付物：**

- 第一阶段前端配置界面
- 第一阶段权限控制与审计查询能力
- 第一阶段基础监控与诊断能力

**阶段完成标准：**

- 管理员可通过页面完成数据服务配置与发布
- 关键配置、发布、停用、测试连接和查询调用可留痕并可检索
- 统一查询运行指标、失败原因和发布后检查清单可使用

### 5.6 第一阶段测试与发布流

**对应 WBS：** `4` 中第一阶段相关内容、`5` 中第一阶段相关内容

**主要工作包：**

- 完成第一阶段单元、集成、E2E、性能与验收测试
- 完成第一阶段部署、发布、回归验证和发布后观测检查
- 完成第一阶段培训、验收和移交准备

**建议顺序：**

1. 第一阶段集成与 E2E 测试
2. 第一阶段性能与资源保护验证
3. 第一阶段验收测试
4. 第一阶段发布与回归验证
5. 第一阶段验收结论确认

**可并行项：**

- 测试文档、发布说明、培训材料可与测试执行并行准备
- 发布后观测检查可与回归验证串联执行

**前置依赖：**

- 第一阶段核心能力和前端主流程已完成联调
- 权限审计、观测和基础资源保护已纳入待测范围

**关键交付物：**

- 第一阶段测试报告
- 发布记录、回归检查记录、回退验证记录
- 第一阶段验收报告

**阶段完成标准：**

- 满足需求规格书第一阶段验收口径
- 第一阶段通过验收后方可进入第二阶段

## 6. 第二阶段实施排期

### 6.1 第二阶段目标与范围

第二阶段目标是在第一阶段基础上建设联邦 SQL 平台能力，支持一个服务直接维护一条联邦 SQL，支持联邦 SQL 解析、校验、优化、执行、方言适配、计划诊断和平台化自助配置能力。

第二阶段边界说明：

- 第二阶段以联邦 SQL 作为数据服务核心定义方式之一
- 第二阶段必须承接第一阶段已有的统一 API、配置管理和发布能力持续演进
- 第二阶段必须纳入联邦 SQL 校验、优化、方言兼容、执行编排、诊断、权限审计和资源保护
- 第二阶段仍需满足单机 4 核 CPU、16G 内存部署基线，不以分布式集群为默认前提

### 6.2 联邦元数据与能力底座流

**对应 WBS：** `3.1`、`3.4`

**主要工作包：**

- 扩展联邦 SQL 相关元数据结构
- 建设数据源能力注册、函数兼容、类型兼容和方言适配能力

**建议顺序：**

1. `3.1` 联邦 SQL 元数据扩展
2. `3.4` 数据源能力模型与方言适配

**可并行项：**

- `3.1` 元数据落库与 `3.4` 能力模型设计可部分并行
- 方言适配和能力注册表可并行实现

**前置依赖：**

- 依赖第一阶段元数据和发布体系稳定
- 依赖第二阶段设计中对能力模型和方言规则的约束已确认

**关键交付物：**

- 联邦 SQL 元数据表与迁移脚本
- 能力注册表与方言适配注册能力

**阶段完成标准：**

- 联邦 SQL 文本、计划、校验日志、能力模型和方言规则可持久化
- 可为后续校验、优化和执行提供统一底座

### 6.3 联邦校验与规划流

**对应 WBS：** `3.2`、`3.3`

**主要工作包：**

- 建设联邦 SQL 解析与校验能力
- 建设逻辑计划生成、规则优化、成本估算与 Join 策略选择能力

**建议顺序：**

1. `3.2` 联邦 SQL 解析与校验能力
2. `3.3` 联邦 SQL 规划与优化能力

**可并行项：**

- 语法校验、来源识别和校验日志落库可并行推进
- 优化规则、统计信息装载和成本估算可在逻辑计划稳定后并行推进

**前置依赖：**

- 依赖 `3.1` 联邦元数据底座
- 依赖 `3.4` 能力模型支持下推判定与方言转换输入

**关键交付物：**

- 联邦 SQL Parser / Validator
- 逻辑计划与优化计划生成能力
- 成本估算和 Join 策略选择能力

**阶段完成标准：**

- 联邦 SQL 可完成语法校验、语义校验和发布前校验
- 能体现 Join Reorder、Filter Pushdown、Project Pushdown 等关键优化能力

### 6.4 联邦执行与优化流

**对应 WBS：** `3.5`、`3.6`

**主要工作包：**

- 建设联邦执行编排、子计划拆分、阶段 DAG 和本地补算能力
- 建设动态过滤、lookup 优化、受控并发和落盘缓冲能力

**建议顺序：**

1. `3.5` 联邦执行编排能力
2. `3.6` 动态过滤与 lookup 优化能力

**可并行项：**

- 远端执行调度与本地补算能力可并行推进
- 动态过滤与 lookup 优化可在联邦执行主干形成后并行接入

**前置依赖：**

- `3.2 -> 3.3 -> 3.5` 构成联邦主链路关键路径
- 依赖 `3.4` 方言适配和能力模型输出可执行子计划

**关键交付物：**

- `PlanSplitter`
- `FederatedPlanExecutor`
- `RemoteQueryExecutor`
- `LocalResultAssembler`
- 资源预算、受控并发、落盘缓冲与快速失败机制

**阶段完成标准：**

- 至少完成一个同构联邦 SQL 场景和一个异构联邦 SQL 场景
- 在单机资源基线下具备预算控制、受控失败和必要时落盘缓冲能力

- 建设联邦审计、诊断和权限控制增强能力

**建议顺序：**

1. `3.7` 联邦计划展示与诊断能力
2. `3.8` 第二阶段前端平台化能力
3. `3.9` 第二阶段联邦诊断与审计增强

- 审计增强和诊断查询能力可与平台前端并行接入

**前置依赖：**

- 权限增强依赖第一阶段权限底座持续扩展

**关键交付物：**

## 8. 阶段性交付与验收计划

### 8.1 第一阶段交付包与验收计划

| 阶段交付包 | 验收输入 | 验收场景 | 验收出口 | 发布前检查项 |
| --- | --- | --- | --- | --- |
| 基础数据服务能力交付包 | 第一阶段功能、测试、发布材料 | Oracle / MySQL / PostgreSQL 连接与查询；统一 API 调用；批量查询；基础跨库；缓存命中；前端配置发布；权限审计；异常反馈；单机资源保护 | 第一阶段验收通过，可进入第二阶段 | 环境部署、配置校验、回归验证、发布后观测、回退预案 |

第一阶段验收重点：

- 能配置至少一种 Oracle、MySQL、PostgreSQL 数据源并成功查询
- 能基于统一 API 成功调用已发布数据服务
- 能完成至少一个跨数据库关联查询场景
- 能完成至少一个批量查询场景
- 能在重复查询场景下命中缓存
- 能通过前端界面完成数据服务配置和发布
- 能体现服务草稿、发布、停用等基本状态流转
- 权限、审计、异常反馈和基础资源保护满足验收口径

### 8.2 第二阶段交付包与验收计划

| 阶段交付包 | 验收输入 | 验收场景 | 验收出口 | 发布前检查项 |
| --- | --- | --- | --- | --- |
| 联邦 SQL 平台能力交付包 | 第二阶段功能、测试、发布、培训与移交材料 | 联邦 SQL 校验与发布；同构联邦场景；异构联邦场景；优化能力；方言兼容；计划与诊断展示；平台自助配置；权限审计；单机资源保护 | 第二阶段验收通过，完成最终交付 | 联邦场景回归、资源保护验证、诊断追溯验证、发布后观测、培训与移交准备 |

第二阶段验收重点：

- 能为一个数据服务直接维护一条联邦 SQL
- 能完成联邦 SQL 的语法校验、发布与执行
- 能完成至少一个同类型数据库联邦 SQL 场景
- 能完成至少一个异构数据库联邦 SQL 场景
- 能体现 Join Reorder、Filter Pushdown、Project Pushdown 的优化能力
- 能支持更复杂表达式和 SQL 方言兼容
- 能通过平台界面完成联邦 SQL 数据服务的自助创建、发布和管理
- 能展示联邦 SQL 的校验结果、执行计划或关键诊断信息
- 能体现权限控制和关键操作审计能力

### 8.3 测试与发布门禁要求

- 每个阶段都必须包含单元、集成、E2E、性能 / 资源保护和验收测试闭环
- 每个阶段都必须包含部署、发布、回归验证、发布后观测和回退验证闭环
- 发现阻断上线的安全、稳定性、权限、数据正确性问题时，不得进入下一阶段或最终交付
- 测试与发布属于阶段门禁，不作为独立于实施主线之外的附属工作
