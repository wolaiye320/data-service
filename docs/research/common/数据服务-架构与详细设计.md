# 数据服务架构与详细设计

## 1. 文档目的

本文档基于《[数据服务需求规格书](/Volumes/osdisk/java_code/data-service/docs/research/common/数据服务-需求规格书.md)》和《[数据服务工程架构说明](/Volumes/osdisk/java_code/data-service/docs/research/common/工程架构说明.md)》编写，用于说明 `data-service` 在 SQL-first 模型下的正式架构方案。

本文档只保留当前确认采用的正确方案，不保留已废弃的目标库驱动、来源手工维护、字段手工维护、参数手工维护和历史讨论过程。

## 2. 设计范围

- 数据源连接管理
- SQL-first 数据服务定义
- 简单 SQL 与联邦 SQL 的统一保存、发布、执行
- 参数快照、字段快照、来源快照自动生成
- 执行计划、校验结果、审计结果持久化
- 本地缓存
- 统一查询 API
- 前端 SQL-first 管理界面
- 日志、审计、异常处理

本文档不包含以下范围：

- 数据新增、修改、删除能力
- 数据同步、ETL、离线计算能力
- 报表分析和 BI 展示能力
- 分布式缓存实现
- 旧模型迁移方案

## 3. 设计原则

- 以 SQL 作为服务定义的唯一事实来源
- 连接只表达数据库连通能力，不表达目标库配置
- 来源、字段、参数均由 SQL 自动解析，不再由用户手工维护
- 保存时生成快照，发布时做完整校验，运行时只读取已发布快照
- 系统只支持只读查询，不支持写入和副作用操作
- 联邦 SQL 允许使用平台 DSL，不要求能在单个数据库中直接执行
- 参数模板统一使用 Doma 风格语法
- `/* */` 只保留给模板语法，不允许写普通块注释
- 旧服务、旧目标库、旧来源、旧字段、旧参数直接删除，不做迁移
- 必须满足单机 4 核 CPU、16G 内存部署基线

## 4. 总体架构

### 4.1 核心模型

系统采用 SQL-first 模型：

- 用户保存服务时，只维护连接、服务基本信息和 SQL
- 后端在保存时自动解析 SQL，生成来源快照、参数快照、字段快照
- 后端在发布时重新校验 SQL、连接、对象、能力和执行计划
- 运行时只读取已发布版本快照执行，不再依赖手工配置的来源、字段、参数或目标库

### 4.2 分层结构

| 层 | 职责 |
| --- | --- |
| 接入层 | 管理接口、统一查询接口、鉴权、请求校验、响应组装 |
| 服务编排层 | 保存、发布、停用、版本切换、快照装载、查询编排 |
| SQL 解析层 | 解析简单 SQL 与联邦 SQL，抽取来源、参数、字段 |
| 校验与规划层 | 只读校验、对象存在性校验、能力校验、执行计划生成 |
| 执行层 | 单源执行、联邦拆分、远端 JDBC 调度、本地整合 |
| 平台支撑层 | 元数据持久化、缓存、审计、日志、资源保护 |

### 4.3 技术边界

| 能力 | 约束 |
| --- | --- |
| SQL 解析 | 必须统一由平台后端完成，前端不得自行定义另一套解析规则 |
| 联邦 SQL | 可使用平台 DSL `connection_code@schema_or_database.table_name` |
| 只读控制 | 仅允许 `select` / `with`，禁止 DML、DDL、存储过程、多语句 |
| 参数模板 | 仅支持 Doma 风格 `/* param */value` 与 `/*%if */` 条件块 |
| 执行计划 | 发布时生成并持久化，运行时优先复用 |
| 资源保护 | 必须提供并发、超时、结果集上限、批量上限和内存保护 |

## 5. 模块设计

### 5.1 数据源连接模块

职责：

- 维护 `DS_CONNECTION`
- 管理连接新增、编辑、测试、启停
- 为 SQL 解析和执行提供连接元数据

处理规则：

- `connectionCode` 全局唯一
- 保存连接时必须执行连通性测试
- 测试连接只校验 JDBC 连通性，不再单独配置目标库
- 停用连接前必须校验是否存在已发布服务引用
- 仅 `ENABLED` 状态连接可参与服务发布和执行

### 5.2 数据服务定义模块

职责：

- 维护 `DS_SERVICE`
- 维护 `DS_SERVICE_VERSION`
- 维护 `DS_CACHE_POLICY`

处理规则：

- 服务编码 `serviceCode` 全局唯一
- 服务状态只允许 `DRAFT`、`PUBLISHED`、`DISABLED`
- 用户保存服务时只录入服务编码、服务名称、SQL 类型、SQL 文本和必要资源限制
- 保存时必须自动解析来源、参数、字段并固化为草稿快照
- 发布时必须生成新版本，不覆盖历史发布版本

### 5.3 SQL 解析模块

职责：

- 解析简单 SQL 与联邦 SQL
- 抽取来源快照
- 抽取参数快照
- 抽取字段快照

处理规则：

- 简单 SQL 依赖默认连接，SQL 中必须显式写 `schema.table`
- 联邦 SQL 依赖平台 DSL，SQL 中必须显式写 `connection_code@schema_or_database.table`
- 解析器必须递归深入子查询、CTE、union 分支
- 多表 SQL 必须显式写表别名
- 复杂表达式输出列若无 `as` 别名则保存失败

### 5.4 校验与规划模块

职责：

- 执行 SQL 只读校验
- 校验连接是否存在且启用
- 校验 SQL 中引用的 schema、database、table 是否真实存在
- 校验联邦 SQL 的能力边界
- 判定复杂表达式、函数、类型转换、日期时间处理等语法能力
- 判定异构数据源之间的方言兼容、下推能力和本地补算边界
- 生成逻辑计划、优化计划和执行计划

处理规则：

- 保存时至少完成语法、对象存在性和参数类型确认校验
- 保存、预览执行、发布和运行阶段必须使用一致的复杂表达式与方言兼容约束口径
- 发布时必须重新解析并重新校验，确认 SQL 与草稿快照一致
- 计划生成失败时不得发布
- 数据源能力不足时必须返回明确失败，不得静默降级

### 5.5 查询执行模块

职责：

- 按 `serviceCode` 加载已发布服务
- 读取当前发布版本快照
- 标准化调用上下文并透传关键字段，如 `tenantId`、调用方标识、链路追踪标识
- 绑定请求参数
- 执行单源查询或联邦查询
- 组装统一响应

处理规则：

- 运行时只读取 `PUBLISHED` 状态服务
- 运行时只依赖已发布版本快照，不再依赖手工来源、字段、参数配置表
- 请求参数必须与 `param_snapshot_json` 一致
- 调用上下文参与权限校验、审计摘要、缓存隔离和后续路由扩展
- SQL 预览执行复用正式执行链路中的解析、校验、规划、资源保护和审计能力，但不生成正式发布版本
- 执行 SQL 时必须应用超时、批量、结果集和并发保护

### 5.6 缓存模块

职责：

- 管理查询结果缓存
- 生成缓存键
- 管理缓存命中与失效

处理规则：

- 缓存键固定包含 `serviceCode`、`version`、请求参数哈希和必要的关键调用上下文摘要
- 仅缓存成功查询结果
- 发布新版本后，旧版本缓存自动失效
- 服务停用后，对应缓存不可继续返回
- 缓存策略变更、显式清理或关键调用上下文变化时，相关缓存必须失效或隔离
- 缓存策略由 `DS_CACHE_POLICY` 控制

### 5.7 权限与审计模块

职责：

- 控制管理接口与查询接口访问边界
- 记录保存、发布、停用、测试连接、校验、执行等关键事件
- 提供审计检索能力

处理规则：

- 调用方只允许访问统一查询接口
- 管理接口必须独立鉴权
- 审计日志必须记录 SQL 版本、解析结果摘要、校验结果摘要、执行摘要和调用上下文摘要
- SQL 预览执行必须纳入独立权限控制和审计记录
- 涉及敏感字段必须脱敏

## 6. 核心数据模型设计

### 6.1 删除的表

| 表 | 删除原因 |
| --- | --- |
| `DS_CATALOG` | 目标库不再独立维护，schema/database 必须写在 SQL 全限定名中 |
| `DS_SOURCE` | 来源定义从 SQL AST 自动解析，不再由表单录入 |
| `DS_FIELD` | 返回字段从 SQL `select` 列表自动解析，不再由表单录入 |
| `DS_PARAM` | 参数从 SQL 模板占位符自动解析，不再由表单录入 |
| `DS_SQL_TEXT` | SQL 原文并入服务版本快照，不再单独维护 |
| `DS_SQL_PLAN` | 旧计划表删除，计划快照并入服务版本或按新结构重建 |
| `DS_SQL_VALIDATE_LOG` | 旧校验日志删除，校验快照并入服务版本或按新结构重建 |

### 6.2 保留的表

| 表 | 保留内容 | 调整说明 |
| --- | --- | --- |
| `DS_CONNECTION` | 连接编码、连接名称、数据库类型、主机、端口、用户名、密码密文、扩展配置、状态、审计字段、删除字段 | 只负责连通性 |
| `DS_SERVICE` | 服务编码、服务名称、SQL 类型、状态、当前版本、资源限制、审计字段、删除字段、租户相关预留字段 | 不再直接保存来源、字段、参数配置 |
| `DS_SERVICE_VERSION` | 版本号、SQL 原文、来源快照、参数快照、字段快照、校验快照、计划快照、状态、发布信息、调用上下文预留摘要 | 作为运行时唯一配置快照来源 |
| `DS_CACHE_POLICY` | 缓存开关、TTL、缓存键策略、上下文隔离策略 | 服务级缓存配置 |
| `DS_SOURCE_CAPABILITY` | 数据源能力配置 | 联邦 SQL 下推、方言、执行策略判断 |
| `DS_DIALECT_RULE` | 数据库方言规则 | SQL 重写和方言适配 |
| `DS_AUDIT_LOG` | 管理、保存、发布、查询、校验、执行审计、调用上下文摘要 | 保留 |

### 6.3 `DS_SERVICE` 最小字段

| 字段 | 说明 |
| --- | --- |
| `id` | 主键 |
| `service_code` | 服务编码，全局唯一 |
| `service_name` | 服务名称 |
| `sql_type` | `SIMPLE_SQL` / `FEDERATED_SQL` |
| `status` | `DRAFT` / `PUBLISHED` / `DISABLED` |
| `current_version` | 当前发布版本 |
| `max_batch_size` | 服务级批量上限 |
| `max_result_rows` | 服务级结果行上限 |
| `query_timeout_seconds` | 单源查询超时 |
| `federated_query_timeout_seconds` | 联邦查询超时 |
| `tenant_id` | 多租户隔离字段预留，按后续正式租户模型启用 |
| `deleted` | 逻辑删除标记 |
| `created_at` / `created_by` | 创建审计字段 |
| `updated_at` / `updated_by` | 更新审计字段 |

### 6.4 `DS_SERVICE_VERSION` 最小字段

| 字段 | 说明 |
| --- | --- |
| `id` | 主键 |
| `service_id` | 关联 `DS_SERVICE.id` |
| `version` | 服务版本号 |
| `status` | `DRAFT` / `PUBLISHED` / `DISABLED` |
| `sql_type` | `SIMPLE_SQL` / `FEDERATED_SQL` |
| `sql_text` | 用户保存的 SQL 原文 |
| `source_snapshot_json` | 保存时从 SQL 解析出的来源快照 |
| `param_snapshot_json` | 保存时从 SQL 解析出的参数快照 |
| `field_snapshot_json` | 保存时从 SQL 解析出的字段快照 |
| `validation_snapshot_json` | 保存或发布时的校验结果快照 |
| `plan_snapshot_json` | 发布时生成的执行计划快照 |
| `request_context_snapshot_json` | 运行与审计所需的调用上下文预留摘要 |
| `published_at` / `published_by` | 发布审计字段 |
| `created_at` / `created_by` | 创建审计字段 |
| `updated_at` / `updated_by` | 更新审计字段 |

### 6.5 快照结构

`source_snapshot_json`：

| 字段 | 说明 |
| --- | --- |
| `connectionCode` | SQL 中显式引用的连接编码；简单 SQL 来自默认连接 |
| `schemaName` | SQL 中显式引用的 schema 名称 |
| `databaseName` | SQL 中显式引用的 database 名称 |
| `tableName` | SQL 中显式引用的表名 |
| `alias` | SQL 表别名 |
| `dbType` | 解析出的连接数据库类型 |

`param_snapshot_json`：

| 字段 | 说明 |
| --- | --- |
| `paramName` | SQL 模板占位符名称 |
| `paramType` | 保存时由用户确认的参数类型 |
| `placeholder` | SQL 模板占位符名称，默认与 `paramName` 一致 |
| `collection` | 是否集合参数 |

`field_snapshot_json`：

| 字段 | 说明 |
| --- | --- |
| `fieldName` | SQL 输出字段名，优先取 `as` 别名 |
| `expression` | 原始 select 表达式 |
| `sortOrder` | 输出顺序 |

`request_context_snapshot_json`：

| 字段 | 说明 |
| --- | --- |
| `tenantId` | 预留的租户标识摘要，用于隔离与审计 |
| `callerId` | 调用方标识摘要 |
| `traceId` | 链路追踪标识摘要 |
| `contextKeys` | 纳入缓存隔离或审计的关键上下文字段名集合 |

## 7. SQL 语法约束

### 7.1 总体规则

| 规则 | 说明 |
| --- | --- |
| 只允许只读 SQL | 仅允许 `select` / `with` |
| SQL 必须显式表达来源 | 不再通过目标库、来源定义表单补充来源 |
| 参数只能使用模板语法 | 禁止 `:param` 旧语法 |
| `/* */` 只保留给模板语法 | 禁止在 SQL 中写普通块注释 |
| 普通说明不写入 SQL | 业务说明写在服务备注或版本说明中 |
| 字段名以 SQL 输出为准 | 返回字段名优先取 `as` 别名 |

### 7.2 简单 SQL 语法

简单 SQL 必须使用数据库内部全限定名。

PostgreSQL：

```sql
select
  o.customer_id as customerId,
  o.order_amount as orderAmount
from public.customer_order o
where o.customer_id = /* customerId */0
```

MySQL：

```sql
select
  c.customer_id as customerId,
  c.customer_name as customerName
from crm.customer c
where c.customer_id = /* customerId */0
```

Oracle：

```sql
select
  e.employee_id as employeeId,
  e.employee_name as employeeName
from HR.employee e
where e.employee_id = /* employeeId */0
```

规则：

| 项 | 规则 |
| --- | --- |
| 连接 | 保存服务时选择一个默认连接，SQL 内不写连接名前缀 |
| schema/database | 必须在表名前显式写出 |
| 表 | 必须可通过默认连接真实访问 |
| 参数 | 从 `/* paramName */默认值` 自动解析 |
| 字段 | 从 `select` 列表自动解析，建议所有输出列显式 `as` |

### 7.3 联邦 SQL 语法

联邦 SQL 使用平台 DSL：

```text
connection_code@schema_or_database.table_name
```

示例：

```sql
select
  c.customer_id as customerId,
  c.customer_name as customerName,
  o.total_amount as totalAmount
from pg_trade@public.customer c
join mysql_billing@crm.order_summary o
  on c.customer_id = o.customer_id
where c.customer_id = /* customerId */0
```

规则：

| 项 | 规则 |
| --- | --- |
| 连接 | `@` 左侧必须是已存在且启用的 `connection_code` |
| schema/database | `@` 右侧第一段必须显式写出 schema 或 database |
| 表 | 第二段必须是表名 |
| 别名 | 多表 SQL 必须显式写别名 |
| Join | Join 条件必须可被解析器识别 |
| CTE / 子查询 / union | 必须纳入解析器支持范围，来源解析递归深入子查询、CTE 与 union 分支 |
| 参数 | 从 SQL 模板占位符自动解析 |
| 字段 | 从最终输出 `select` 列表解析，不做业务语义推断 |

### 7.4 参数模板语法

必填参数：

```sql
where customer_id = /* customerId */0
```

非必填参数：

```sql
where 1 = 1
/*%if customerId != null */
  and customer_id = /* customerId */0
/*%end*/
```

集合参数：

```sql
where customer_id in /* customerIds */(0)
```

规则：

| 项 | 规则 |
| --- | --- |
| 参数名 | 从占位符自动解析 |
| 参数类型 | 保存服务时由用户确认 |
| 是否必填 | 不单独维护，靠 SQL 是否处于动态条件块表达 |
| 默认值 | 优先写在模板占位符后的示例字面量中 |
| 格式 | 日期、时间等格式由参数类型和调用协议约定 |

## 8. 后端实现设计

### 8.1 分层与目录职责

| 模块或包路径 | 主要职责 |
| --- | --- |
| `data-service-app` | Spring Boot 启动与运行期装配 |
| `data-service-common` | 公共异常、上下文、枚举、工具 |
| `data-service-core.web` | HTTP 接入层 |
| `data-service-core.datasource` | 连接管理与 JDBC URL 构造 |
| `data-service-core.service` | 服务保存、发布、版本切换、快照管理 |
| `data-service-core.query` | 统一查询编排 |
| `data-service-core.query.executor` | SQL 模板渲染、参数绑定、只读校验、结果映射 |
| `data-service-core.query.cache` | 查询缓存支撑 |
| `data-service-core.query.protection` | 资源保护支撑 |
| `data-service-core.federation` | 联邦 SQL 解析、校验、规划、执行、方言、能力 |
| `data-service-core.audit` | 审计写入与审计检索 |
| `data-service-core.security` | 权限与平台访问控制 |
| `data-service-core.repository` | 元数据库访问 |

### 8.2 连接管理设计

处理逻辑：

1. 根据 `connectionCode` 读取连接配置
2. 根据 `dbType` 选择驱动
3. 初始化或复用连接池
4. 执行 JDBC 连通性测试
5. 提供运行时连接访问能力

### 8.3 服务保存设计

处理逻辑：

1. 接收服务基本信息、SQL 类型、SQL 文本
2. 简单 SQL 读取默认连接；联邦 SQL 从 SQL 本文解析连接
3. 解析 SQL AST
4. 抽取来源、参数、字段
5. 校验连接、schema/database、table 是否真实存在
6. 前端确认参数类型
7. 生成草稿快照并写入 `DS_SERVICE_VERSION`
8. 预留调用上下文摘要字段，用于后续租户隔离、缓存隔离和审计扩展

### 8.4 服务发布设计

处理逻辑：

1. 读取草稿版本 SQL 和快照
2. 重新解析 SQL，确认 SQL 与快照一致
3. 执行只读校验、对象存在性校验、权限校验、能力校验
4. 生成逻辑计划、优化计划和执行计划
5. 写入校验快照和计划快照
6. 切换服务为已发布版本
7. 记录审计日志

### 8.5 查询执行设计

处理逻辑：

1. 根据 `serviceCode` 加载 `PUBLISHED` 服务
2. 读取当前发布版本快照
3. 标准化调用上下文并校验租户、调用方和链路追踪等关键字段
4. 根据 `param_snapshot_json` 校验和转换请求参数
5. 根据 `plan_snapshot_json` 决定单源执行、远端下推或本地整合
6. 根据 `source_snapshot_json` 获取连接并生成目标数据库 SQL
7. 结合服务版本、请求参数和关键调用上下文生成缓存键并应用缓存
8. 执行 SQL
9. 根据 `field_snapshot_json` 组装统一响应
10. 记录缓存、日志和审计摘要

### 8.6 发布校验设计

发布前必须完成以下校验：

- `DS_SERVICE` 基本信息完整
- SQL 语法合法
- SQL 只读合法
- 连接存在且启用
- SQL 中引用的 schema、database、table 真实存在
- 参数快照完整且参数类型已确认
- 字段快照完整且复杂表达式均有别名
- 复杂表达式、异构方言和联邦能力边界已完成一致性校验
- 联邦 SQL 已通过能力校验
- 联邦 SQL 已生成执行计划
- 资源限制配置完整

## 10. 核心流程

### 10.1 数据源配置流程

1. 提交连接信息
2. 校验唯一性与必填项
3. 执行连接测试
4. 保存 `DS_CONNECTION`

### 10.2 服务保存流程

1. 创建或编辑服务草稿
2. 录入 SQL
3. 解析 SQL
4. 自动识别来源、参数、字段
5. 校验连接和对象存在性
6. 用户确认参数类型
7. 保存 `DS_SERVICE`
8. 保存一条 `DS_SERVICE_VERSION(status=DRAFT)`

### 10.3 服务发布流程

1. 读取草稿版本
2. 重新解析 SQL
3. 执行发布校验
4. 生成执行计划
5. 写入校验快照和计划快照
6. 切换服务为 `PUBLISHED`
7. 记录发布审计

### 10.4 SQL 预览执行流程

1. 接收草稿 SQL、预览参数和调用上下文
2. 执行权限校验、只读校验和资源保护校验
3. 解析 SQL 并生成来源、参数、字段快照
4. 校验连接、对象存在性、复杂表达式、异构方言和联邦能力边界
5. 生成预览执行计划
6. 执行受控只读查询
7. 返回预览结果、执行耗时和关键诊断摘要
8. 记录预览执行审计，不生成正式服务版本

### 10.5 查询执行流程

1. 接收统一查询请求
2. 加载已发布服务和当前版本快照
3. 标准化调用上下文并校验租户、调用方和链路追踪等关键字段
4. 绑定请求参数
5. 根据服务版本、请求参数和关键调用上下文生成缓存键并应用缓存
6. 执行单源或联邦查询
7. 组装响应
8. 记录日志和审计摘要

## 12. 异常与安全设计

### 12.1 配置阶段异常

- 数据源不可连接
- 服务编码重复
- SQL 语法非法
- SQL 非只读
- 连接不存在或未启用
- schema/database/table 不存在
- 参数类型未确认
- 执行计划生成失败

### 12.2 运行阶段异常

- 服务不存在
- 服务未发布
- 参数不合法
- 批量超限
- 查询超时
- 数据源不可用
- 联邦查询执行失败
- 本地整合超限

### 12.3 安全控制

- 连接密码仅保存密文
- 配置展示对敏感字段脱敏
- 动态 SQL 禁止字符串拼接执行
- 联邦 SQL 必须由系统统一解析与执行
- 查询接口禁止非查询语句
- 管理接口与查询接口路由隔离

## 13. 性能设计

- 连接池按数据源复用
- 高频服务启用本地缓存
- 单批次查询上限必须可配置
- 单次查询结果上限必须可配置
- 单次查询与联邦查询超时必须可配置
- `serviceCode`、`connectionCode`、外键字段必须建立索引
- 联邦 SQL 执行优先减少跨源数据搬运
- 远端执行并发度必须可控
- 中间结果应支持流式处理与必要时落盘
- 本地补算必须具备内存上限和结果集上限保护
- 所有默认参数必须适配单机 4 核 CPU、16G 内存

## 15. 旧服务处理

本次 SQL-first 重构不做历史兼容和数据迁移。

| 对象 | 处理方式 |
| --- | --- |
| 旧连接 | 可保留基础连接信息；若字段结构不兼容则清空重建 |
| 旧目标库 | 删除 |
| 旧服务 | 删除 |
| 旧来源定义 | 删除 |
| 旧参数定义 | 删除 |
| 旧字段定义 | 删除 |
| 旧服务版本 | 删除 |
| 旧 SQL 文本和计划 | 删除 |
| 旧缓存策略 | 删除或随服务删除 |
| 旧审计日志 | 可按运维需要备份后清空；新分支不依赖旧审计 |

落地规则：

| 项 | 规则 |
| --- | --- |
| Flyway | 新分支可以直接重建元数据库基线，不编写旧模型迁移脚本 |
| 前端 | 删除目标库、来源、字段、参数维护页面或表单区 |
| 后端 | 删除目标库、来源、字段、参数的管理接口和运行时依赖 |
| 测试 | 删除旧模型相关测试，重建 SQL-first 测试基线 |
