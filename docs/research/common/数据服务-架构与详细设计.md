# 数据服务架构与详细设计

## 1. 文档目的

本文档基于《[数据服务需求规格书](/Volumes/osdisk/java_code/data-service/docs/research/common/数据服务-需求规格书.md)》和《[数据服务工程架构说明](/Volumes/osdisk/java_code/data-service/docs/research/common/工程架构说明.md)》编写，用于说明 `data-service` 在 SQL-first 模型下的正式架构方案。

本文档只保留当前确认采用的正确方案，不保留已废弃的目标库驱动、来源手工维护、字段手工维护、参数手工维护和历史讨论过程。

## 2. 设计范围

- 数据源连接管理
- SQL-first 数据服务定义
- 简单 SQL 与联邦 SQL 的统一保存、发布、执行
- 参数快照、字段快照、来源快照自动生成
- 执行计划、校验结果、审计结果持久化
- 本地缓存
- 统一查询 API
- 前端 SQL-first 管理界面
- 日志、审计、异常处理

本文档不包含以下范围：

- 数据新增、修改、删除能力
- 数据同步、ETL、离线计算能力
- 报表分析和 BI 展示能力
- 分布式缓存实现
- 旧模型迁移方案

## 3. 设计原则

- 以 SQL 作为服务定义的唯一事实来源
- 连接只表达数据库连通能力，不表达目标库配置
- 来源、字段、参数均由 SQL 自动解析，不再由用户手工维护
- 保存时生成快照，发布时做完整校验，运行时只读取已发布快照
- 系统只支持只读查询，不支持写入和副作用操作
- 联邦 SQL 允许使用平台 DSL，不要求能在单个数据库中直接执行
- 参数模板统一使用 Doma 风格语法
- `/* */` 只保留给模板语法，不允许写普通块注释
- 旧服务、旧目标库、旧来源、旧字段、旧参数直接删除，不做迁移
- 必须满足单机 4 核 CPU、16G 内存部署基线

## 4. 总体架构

### 4.1 核心模型

系统采用 SQL-first 模型：

- 用户保存服务时，只维护连接、服务基本信息和 SQL
- 后端在保存时自动解析 SQL，生成来源快照、参数快照、字段快照
- 后端在发布时重新校验 SQL、连接、对象、能力和执行计划
- 运行时只读取已发布版本快照执行，不再依赖手工配置的来源、字段、参数或目标库

### 4.2 分层结构

| 层 | 职责 |
| --- | --- |
| 接入层 | 管理接口、统一查询接口、鉴权、请求校验、响应组装 |
| 服务编排层 | 保存、发布、停用、版本切换、快照装载、查询编排 |
| SQL 解析层 | 解析简单 SQL 与联邦 SQL，抽取来源、参数、字段 |
| 校验与规划层 | 只读校验、对象存在性校验、能力校验、执行计划生成 |
| 执行层 | 单源执行、联邦拆分、远端 JDBC 调度、本地整合 |
| 平台支撑层 | 元数据持久化、缓存、审计、日志、资源保护 |

### 4.3 技术边界

| 能力 | 约束 |
| --- | --- |
| SQL 解析 | 必须统一由平台后端完成，前端不得自行定义另一套解析规则 |
| 联邦 SQL | 可使用平台 DSL `connection_code@schema_or_database.table_name` |
| 只读控制 | 仅允许 `select` / `with`，禁止 DML、DDL、存储过程、多语句 |
| 参数模板 | 仅支持 Doma 风格 `/* param */value` 与 `/*%if */` 条件块 |
| 执行计划 | 发布时生成并持久化，运行时优先复用 |
| 资源保护 | 必须提供并发、超时、结果集上限、批量上限和内存保护 |

## 5. 模块设计

### 5.1 数据源连接模块

职责：

- 维护 `DS_CONNECTION`
- 管理连接新增、编辑、测试、启停
- 为 SQL 解析和执行提供连接元数据

处理规则：

- `connectionCode` 全局唯一
- 保存连接时必须执行连通性测试
- 测试连接只校验 JDBC 连通性，不再单独配置目标库
- 停用连接前必须校验是否存在已发布服务引用
- 仅 `ENABLED` 状态连接可参与服务发布和执行

### 5.2 数据服务定义模块

职责：

- 维护 `DS_SERVICE`
- 维护 `DS_SERVICE_VERSION`
- 维护 `DS_CACHE_POLICY`

处理规则：

- 服务编码 `serviceCode` 全局唯一
- 服务状态只允许 `DRAFT`、`PUBLISHED`、`DISABLED`
- 用户保存服务时只录入服务编码、服务名称、SQL 类型、SQL 文本和必要资源限制
- 保存时必须自动解析来源、参数、字段并固化为草稿快照
- 发布时必须生成新版本，不覆盖历史发布版本

### 5.3 SQL 解析模块

职责：

- 解析简单 SQL 与联邦 SQL
- 抽取来源快照
- 抽取参数快照
- 抽取字段快照

处理规则：

- 简单 SQL 依赖默认连接，SQL 中必须显式写 `schema.table`
- 联邦 SQL 依赖平台 DSL，SQL 中必须显式写 `connection_code@schema_or_database.table`
- 解析器必须递归深入子查询、CTE、union 分支
- 多表 SQL 必须显式写表别名
- 复杂表达式输出列若无 `as` 别名则保存失败

### 5.4 校验与规划模块

职责：

- 执行 SQL 只读校验
- 校验连接是否存在且启用
- 校验 SQL 中引用的 schema、database、table 是否真实存在
- 校验联邦 SQL 的能力边界
- 判定复杂表达式、函数、类型转换、日期时间处理等语法能力
- 判定异构数据源之间的方言兼容、下推能力和本地补算边界
- 生成逻辑计划、优化计划和执行计划

处理规则：

- 保存时至少完成语法、对象存在性和参数类型确认校验
- 保存、预览执行、发布和运行阶段必须使用一致的复杂表达式与方言兼容约束口径
- 发布时必须重新解析并重新校验，确认 SQL 与草稿快照一致
- 联邦能力读取统一通过数据源能力服务完成，不得在发布、规划、执行链路中散落直查能力表
- 计划生成失败时不得发布
- 数据源能力不足时必须返回明确失败，不得静默降级

数据源能力编码与作用域模型：

| 维度 | 当前口径 | 说明 |
| --- | --- | --- |
| ownerLevel | `CONNECTION` | 当前 `DS_SOURCE_CAPABILITY` 记录挂载在具体连接上，发布与规划阶段按连接聚合读取 |
| scopeType | `GLOBAL` / `SCHEMA` / `TABLE` / `CUSTOM` | `GLOBAL` 表示该连接全局生效；`SCHEMA`、`TABLE` 和其他自定义值统一视为可扩展作用域 |
| scopeValue | 可空 | `GLOBAL` 为空；其余作用域保存对象标识，如 schema 名、表名或扩展值 |
| capabilityCode | 例如 `FILTER_PUSHDOWN`、`JOIN` | 统一作为能力判定和计划摘要中的稳定编码 |
| capabilityValue | 例如 `SUPPORTED` | 表示当前作用域下能力结论，后续细粒度判定在此基础上扩展 |

补充约束：

- 当前最小闭环先支持“连接级挂载 + 全局/可扩展作用域”两层语义
- 后续若补充库类型默认能力，可在不破坏现有 `ownerLevel + scopeType + scopeValue` 结构的前提下扩展
- 发布计划快照必须保留 `capabilitySummaries` 摘要，便于前端和审计定位能力来源与作用域

方言规则类型与优先级：

| 维度 | 当前口径 | 说明 |
| --- | --- | --- |
| 默认规则层级 | `dbType` | 由 `DS_DIALECT_RULE.db_type` 承载数据库类型默认规则 |
| 覆盖规则层级 | `connectionId` | 连接级规则覆盖同 `ruleCode` 的 dbType 默认规则 |
| 优先级顺序 | `CONNECTION_OVERRIDE` > `DB_TYPE_DEFAULT` | 生效规则集合先装载 dbType 默认规则，再用连接级同编码规则覆盖 |
| 当前规则类型 | `FUNCTION_MAPPING` | 当前最小闭环先支持函数名映射，不提前展开复杂表达式判定 |

补充约束：

- 方言规则加载必须统一通过方言规则服务完成，不得在执行链路中散落分别查询 `findEnabledByConnectionId` 与 `findEnabledByDbType`
- SQL 改写入口当前挂在预览执行链路，先保证规则优先级和统一入口稳定，再在后续表达式判定阶段扩展

表达式判定输入与诊断模型：

| 维度 | 当前口径 | 说明 |
| --- | --- | --- |
| 输入来源 | `sqlText` + 连接方言上下文 | 判定器基于 SQL 文本识别复杂表达式，并按默认连接方言加载重写上下文 |
| 表达式类型 | `CASE` / `CAST` / `DATETIME` / `STRING` / `AGGREGATE` | 当前最小闭环覆盖需求规格书要求的核心复杂表达式类别 |
| 判定结果 | `SUPPORTED` / `REWRITABLE` / `UNSUPPORTED` | 明确区分可直接支持、依赖方言规则改写、当前明确不支持 |
| 失败诊断 | `type + detail + connectionCode` | 不支持时必须返回表达式类型、失败细节和可用的连接定位信息 |

补充约束：

- 保存与发布阶段必须复用同一表达式判定器，避免不同阶段出现口径漂移
- 当前最小闭环对 JSON/复杂类型 `CAST` 直接判为 `UNSUPPORTED`
- 保存与发布校验快照必须保留 `expressionSupport` 摘要，供前端和审计读取

联邦组合与能力边界校验模型：

| 维度 | 当前口径 | 说明 |
| --- | --- | --- |
| 组合矩阵 | `POSTGRESQL` / `MYSQL` / `ORACLE` 单源、同构、异构组合 | 只要来源库类型全部落在正式支持矩阵内，即允许进入下一步能力校验 |
| 校验类型 | `COMBINATION` / `FILTER_PUSHDOWN` / `PROJECT_PUSHDOWN` / `JOIN_REORDER` / `AGGREGATE_PUSHDOWN` / `FUNCTION_PUSHDOWN` / `LOCAL_COMPENSATION` | 统一输出稳定检查项编码，供前端和审计复用 |
| 结果等级 | `PASS` / `WARN` / `FAIL` | 当前最小闭环先使用 `PASS` 与 `FAIL`，为后续细粒度告警预留 `WARN` |
| 失败口径 | `type + detail + relatedConnections` | 失败时必须定位到具体能力项和受影响连接 |

补充约束：

- 联邦能力校验只做“能否进入计划阶段”的边界判定，不提前承担完整逻辑计划职责
- 缺少任何必要下推能力配置时，必须明确失败，不得用本地补算兜底掩盖
- 联邦校验摘要由统一联邦校验服务输出，发布链路不得再散落拼装错误消息

逻辑计划节点模型：

| 节点类型 | 当前口径 | 说明 |
| --- | --- | --- |
| `SCAN` | 来源扫描节点 | 每个来源快照至少对应一个扫描节点 |
| `JOIN` | 多来源关联节点 | 检测到多源 `join` 时生成 |
| `FILTER` | 过滤节点 | 检测到 `where` 时生成 |
| `AGGREGATE` | 聚合节点 | 检测到 `count/sum/avg/min/max` 时生成 |
| `PROJECT` | 投影节点 | 基于字段快照生成最终投影 |
| `PARAM_BIND` | 参数绑定节点 | 存在参数快照时追加到计划尾部 |

补充约束：

- 当前最小闭环按“来源快照 + 字段快照 + SQL 结构特征”生成稳定逻辑计划，不提前实现完整 AST 规划器
- 预览与发布计划快照必须同时包含 `logicalPlan` 与 `diagnosticSummary`
- `logicalPlan.rootNodeId` 必须稳定指向当前计划尾节点，便于后续扩展优化计划和执行计划

Join 调序输入与摘要模型：

| 维度 | 当前口径 | 说明 |
| --- | --- | --- |
| 输入因子 | `connectionCode` / `dbType` / `filterScore` / `estimatedRows` / `joinType` | 当前最小闭环按显式输入结构记录调序依据，避免隐式经验值 |
| 调序规则 | 先按 `filterScore` 倒序，再按 `estimatedRows` 升序 | 优先让过滤更强、估算规模更小的来源靠前 |
| 调序结果 | `originalSources` / `reorderedSources` / `applied` / `reason` | 计划快照必须保留原顺序、调序后顺序和原因 |

补充约束：

- 当前 Join Reorder 只改变逻辑计划中的来源顺序摘要，不直接改写用户 SQL 文本
- 未检测到多源 `join` 或调序结果与原顺序一致时，也必须输出诊断摘要说明“未发生调序”

过滤下推摘要模型：

| 维度 | 当前口径 | 说明 |
| --- | --- | --- |
| 条件抽取范围 | `where` 子句按 `and` 颗粒拆分 | 当前最小闭环先覆盖主查询过滤条件，保留后续扩展 `join on` 与子查询过滤的空间 |
| 下推判定 | `FILTER_PUSHDOWN` + `capabilityValue=SUPPORTED` | 只有连接已声明支持且条件本身不含当前明确禁止的复杂组合时才记为可下推 |
| 摘要字段 | `extractedConditions` / `pushdownConditions` / `residualConditions` / `rewrittenPushdownFragment` | 预览与发布计划快照统一输出过滤下推摘要，便于前端和审计定位 |
| 残余口径 | 未下推条件进入 `residualConditions` | 当前最小闭环先输出残余过滤摘要，不直接改写真实执行 SQL |

补充约束：

- 过滤下推能力判断必须同时校验能力编码和值，禁止仅因存在同名能力记录就误判可下推
- 过滤节点详情需回写“已下推数量 / 残余数量”摘要，避免计划诊断与能力边界脱节

统一查询参数绑定与诊断模型：

| 维度 | 当前口径 | 说明 |
| --- | --- | --- |
| 快照输入 | `param_snapshot_json` | 正式查询运行时只读取发布版本参数快照，不再依赖请求临时推断参数类型 |
| 对齐规则 | 缺失参数、未定义参数、集合形态不匹配直接失败 | 请求参数名必须与已发布参数快照完全对齐 |
| 类型转换 | `LONG` / `INTEGER` / `DOUBLE` / `DECIMAL` / `BOOLEAN` / `DATE` / `LOCAL_DATE_TIME` / `STRING` | 运行时先做显式类型转换，再进入执行链路 |
| 诊断结构 | `errorCode + message + details[]` | `details` 至少返回 `path`、`reasonCode`、`paramName`、`expectedType`、`actualType`、`collection` |

补充约束：

- 参数校验失败必须在执行 SQL 前返回，不得继续依赖执行阶段隐式报错兜底
- 参数诊断路径统一使用 `inputs[index].params.paramName` 结构，便于批量查询逐项定位

单源正式查询执行模型：

| 维度 | 当前口径 | 说明 |
| --- | --- | --- |
| 执行输入 | `sqlText + paramSnapshotJson + boundParams` | 正式查询先按发布参数快照构造 JDBC 执行输入 |
| SQL 绑定 | `PreparedStatement` 参数化绑定 | 正式查询不得再通过字符串拼接注入参数值 |
| 结果映射 | `fieldSnapshotJson` 驱动字段顺序 | 响应行字段按发布字段快照顺序稳定输出 |
| 单项摘要 | `items[index].meta.elapsedMs + diagnosticSummary` | 成功项返回单源执行耗时、连接、字段顺序和绑定参数数量摘要 |

补充约束：

- 当前最小闭环仅支持 `SIMPLE_SQL` 单源正式查询，联邦执行由后续 `7.5.*` 承接
- 单源正式查询优先复用现有连接、只读校验和方言改写能力，但执行职责已从统一查询编排层拆到独立执行器

联邦正式查询执行模型：

| 维度 | 当前口径 | 说明 |
| --- | --- | --- |
| 子查询拆分 | `FederatedQuerySplitter` | 基于来源快照、Join 调序摘要和过滤下推摘要，按连接拆成远端任务 |
| 远端执行 | 顺序调度各远端任务 + 跨请求并发闸门 | 当前最小闭环先保证结果正确性，不提前引入任务级并发调度，但必须限制联邦查询同时占用的远端执行名额 |
| 本地整合 | 等值 Join + 残余过滤 + 字段投影 | 先支持等值 Join、本地简单过滤和字段快照驱动投影 |
| 联邦诊断 | `items[index].meta.diagnosticSummary` | 返回 `taskCount`、`joinConditionCount`、`residualFilterCount`、`taskSummaries`、`rootNodeId`、`federatedQueryTimeoutSeconds` |

补充约束：

- 当前最小闭环仅支持 `FEDERATED_SQL` 下的等值 Join、本地 `AND` 结构简单残余过滤和列级字段投影
- 联邦远端任务仍按顺序调度，但跨请求必须受 `maxConcurrentQueries` 闸门控制，超限直接受控失败
- 单源 JDBC 超时与联邦总耗时超时统一映射到资源保护错误，当前最小闭环回写 `failureStage=TIMEOUT_GUARD`
- 复杂残余过滤、排序、聚合和更高阶本地补算边界，仍由后续资源保护与联邦增强任务继续承接

批量查询执行与状态模型：

| 维度 | 当前口径 | 说明 |
| --- | --- | --- |
| 输入结构 | `inputs[]` | 单次与批量查询继续共用一套统一契约 |
| 结果对应 | `items[index]` | 每组输入按原始索引稳定回填到结果项 |
| 批量状态 | `SUCCESS` / `FAILURE` / `PARTIAL_FAILURE` | 全成功返回 `SUCCESS`，全失败返回 `FAILURE`，部分成功返回 `PARTIAL_FAILURE` |
| 批量元信息 | `requestedBatchSize + successCount + failureCount` | 响应级 `meta` 统一暴露批量规模和成功失败汇总 |

补充约束：

- 当前最小闭环批量执行仍按顺序执行，先保证逐项错误结构和结果对应关系稳定
- 批量级状态只反映当前请求内各项成功失败汇总，不替代单项 `error/details` 诊断
- 当前最小闭环已在统一查询入口接入 `maxBatchSize` 守卫；批量规模超限时直接返回 `400`
- 批量超限错误响应补充 `diagnosticSummary.failureStage=BATCH_GUARD`、`protectionType=BATCH_SIZE`、`maxBatchSize`、`actualBatchSize`

统一查询响应组装模型：

| 维度 | 当前口径 | 说明 |
| --- | --- | --- |
| 单项元信息 | `items[index].meta.elapsedMs + cacheHit + diagnosticSummary` | 成功项与失败项统一返回同名 `meta` 结构，失败项当前 `elapsedMs` 允许为空 |
| 失败摘要 | `failureStage + detailCount` | 参数校验失败、联邦执行失败等场景统一在 `diagnosticSummary` 中回写阶段和明细数量 |
| 错误映射 | `error.errorCode + message + details[]` | 参数错误、联邦错误和业务异常统一走同一组装器输出 |
| trace 透传 | `requestContext.traceId + meta.traceId` | 请求体缺失 `traceId` 时继续回退 HTTP `X-Trace-Id`，成功与失败链路都保持一致 |

补充约束：

- 不再允许失败项 `items[index].meta` 返回 `null`，避免调用方按成功/失败分支解析不同字段树
- 当前阶段已接入进程内结果缓存，命中时直接短路执行并返回 `cacheHit=true`，后续缓存任务继续补齐失效、清理和跨实例能力
- 结果集保护失败统一回写 `failureStage=RESULT_GUARD`；当前最小闭环补充 `protectionType=RESULT_ROWS`、`guardStage`、`maxResultRows`、`actualRows`
- 联邦远端子查询若因 `maxResultRows` 触发截断，必须在联邦执行阶段直接转成资源保护失败，禁止静默返回不完整整合结果

投影裁剪与字段映射摘要模型：

| 维度 | 当前口径 | 说明 |
| --- | --- | --- |
| 输入来源 | `fieldSnapshotJson` + 来源快照 + 能力摘要 | 投影裁剪严格基于字段快照顺序，不再临时推导展示列顺序 |
| 下推判定 | `PROJECT_PUSHDOWN` + `capabilityValue=SUPPORTED` | 仅简单列或 `*` 投影纳入当前最小闭环；复杂表达式先保留为残余映射 |
| 摘要字段 | `requestedFields` / `pushdownFields` / `residualFields` / `fieldMapping` | 统一输出请求字段、已下推字段、残余字段和本地字段映射一致性结果 |
| 字段映射一致性 | `fieldMapping.consistent` + `detail` | 用于约束输出字段名称、顺序与快照一致，发现重复别名时直接暴露风险 |

补充约束：

- 预览与发布计划快照必须复用同一份投影摘要结构，不得出现 preview/publish 口径漂移
- 当前最小闭环只在逻辑计划摘要层反映投影裁剪与下推，不直接改写真实 JDBC 执行列清单

本地补算守卫模型：

| 维度 | 当前口径 | 说明 |
| --- | --- | --- |
| 允许操作 | `RESIDUAL_FILTER` / `RESIDUAL_PROJECT_MAPPING` | 当前最小闭环只允许残余过滤和残余字段映射进入本地补算候选清单 |
| 语义禁止场景 | 本地排序、聚合投影、字段映射不一致 | 一旦命中这些场景，必须在发布阶段明确失败，不得继续用本地补算兜底 |
| 资源阈值 | `maxResultRows <= 1000` 且 `sourceCount <= 3`，执行期 `maxLocalCompIntermediateRows` | 当前最小闭环先用固定阈值保护本地补算规模，执行期再用中间结果行数阈值阻断高风险本地整合 |
| 失败口径 | `type=SEMANTIC|RESOURCE` + `detail` | 失败必须区分语义禁止与资源保护触发，便于前端和审计定位 |

补充约束：

- 本地补算守卫与联邦能力校验分层协作：能力校验负责“是否具备下推前提”，补算守卫负责“残余操作是否还能安全留在本地”
- 当前最小闭环已把执行期中间结果守卫接入联邦本地 Join 与残余过滤后检测点，超限统一回写 `failureStage=MEMORY_GUARD`
- 当前阶段内存保护采用“中间结果行数阈值”近似控制，不做 JVM 实时内存测量；后续若引入落盘或更精细估算，再与统一资源保护模型收敛

统一计划快照模型：

| 维度 | 当前口径 | 说明 |
| --- | --- | --- |
| 统一结构 | `stage` / `sqlType` / `sourceCount` / `paramCount` / `stages` / `capabilitySummaries` / `logicalPlan` / `diagnosticSummary` | 预览与发布统一复用同一份计划快照 JSON 结构 |
| 预览阶段 | `PREVIEW` | 保留能力摘要、逻辑计划与阶段列表，便于前端直接展示 |
| 发布阶段 | `PUBLISH` | 与预览使用同名字段，避免后续展示与审计解析分叉 |
| 展示 DTO | `planSnapshot` | 在保留 `planSnapshotJson` 原文字段的同时，额外提供结构化精简展示对象 |

补充约束：

- 不删除既有 `planSnapshotJson` 字段，避免破坏接口兼容性；结构化 DTO 作为增量能力补充
- 结构化 `planSnapshot` 当前只暴露前端与审计展示必需字段，完整逻辑计划仍从 `planSnapshotJson` 读取

统一查询请求与上下文标准化模型：

| 维度 | 当前口径 | 说明 |
| --- | --- | --- |
| 查询入口 | `POST /api/data-services/query` | 当前最小闭环统一承接单次与批量查询 |
| 请求结构 | `serviceCode + inputs + requestContext` | `inputs` 为统一数组结构，单次查询也按单元素数组承载 |
| 响应结构 | `serviceCode + serviceVersion + status + items + meta + requestContext` | 保持成功/部分失败统一外形，便于调用方稳定消费 |
| 上下文字段 | `tenantId` / `callerId` / `traceId` / `contextKeys` | 先做字段清洗、去空白、去重和默认 trace 回填 |
| 摘要字段 | `contextSummaryKeys` | 输出当前实际参与缓存/审计候选摘要的上下文字段名集合 |

补充约束：

- 当前最小闭环先保证统一查询链路内部使用同一份标准化上下文对象，不在各服务层重复清洗原始请求
- 当前最小闭环把 `requestContext.callerId` 作为查询调用方认证契约；缺失时统一返回 `403 ACCESS_DENIED`
- 查询权限失败当前复用统一错误响应模型，继续透传 `traceId`
- 当请求级 `traceId` 缺失但 HTTP Header 中存在 `X-Trace-Id` 时，错误响应必须回填该值，避免失败链路断追踪

### 5.5 查询执行模块

职责：

- 按 `serviceCode` 加载已发布服务
- 读取当前发布版本快照
- 标准化调用上下文并透传关键字段，如 `tenantId`、调用方标识、链路追踪标识
- 绑定请求参数
- 执行单源查询或联邦查询
- 组装统一响应

处理规则：

- 运行时只读取 `PUBLISHED` 状态服务
- 运行时只依赖已发布版本快照，不再依赖手工来源、字段、参数配置表
- 请求参数必须与 `param_snapshot_json` 一致
- 调用上下文参与权限校验、审计摘要、缓存隔离和后续路由扩展
- SQL 预览执行复用正式执行链路中的解析、校验、规划、资源保护和审计能力，但不生成正式发布版本
- 执行 SQL 时必须应用超时、批量、结果集和并发保护

### 5.6 缓存模块

职责：

- 管理查询结果缓存
- 生成缓存键
- 管理缓存命中与失效

处理规则：

- 缓存键固定包含 `serviceCode`、`version`、请求参数哈希和必要的关键调用上下文摘要
- 仅缓存成功查询结果
- 发布新版本后，旧版本缓存自动失效
- 服务停用后，对应缓存不可继续返回
- 缓存策略变更、显式清理或关键调用上下文变化时，相关缓存必须失效或隔离
- 缓存策略由 `DS_CACHE_POLICY` 控制

缓存键最小组成规则：

| 组成项 | 是否必选 | 规则 |
| --- | --- | --- |
| `serviceCode` | 是 | 固定使用服务编码，避免不同服务共享结果 |
| `version` | 是 | 固定使用当前发布版本，禁止跨版本复用 |
| `paramHash` | 是 | 对标准化后的请求参数集合做稳定哈希；参数名按字典序排序，空值、集合顺序和类型差异必须进入哈希输入 |
| `contextDigest` | 条件必选 | 当 `DS_CACHE_POLICY.context_keys_json` 非空时，按声明顺序提取对应调用上下文字段并生成稳定摘要；为空时不写入缓存键 |

补充约束：

- 默认模板采用 `data-service:{serviceCode}:v{version}:{paramHash}`
- 当存在 `contextDigest` 时，推荐扩展为 `data-service:{serviceCode}:v{version}:{paramHash}:{contextDigest}`
- `paramHash` 只基于请求参数值生成，不得把 `serviceCode`、`version` 重复混入
- `contextDigest` 只包含 `contextKeys` 声明过的字段，未声明字段即使透传也不得影响缓存键
- `tenantId` 一旦被纳入 `contextKeys`，必须参与缓存隔离，禁止跨租户复用

缓存失效触发条件：

| 触发场景 | 处理口径 | 最小验证点 |
| --- | --- | --- |
| TTL 到期 | 条目自然失效，下次请求重新执行并回填缓存 | 同一键在 TTL 前命中、TTL 后失效 |
| 发布新版本 | 新版本直接切换到新 `version` 命名空间；旧版本缓存不得被新版本命中 | 同一 `serviceCode` 不同版本形成不同缓存键 |
| 服务停用 | 停用后对应服务缓存不得继续返回；当前最小闭环通过关闭 `DS_CACHE_POLICY.enabled` 实现 | 停用后缓存策略变为关闭，查询链路不得再命中 |
| 缓存策略变更 | `enabled`、`ttlSeconds`、`contextKeys`、`cacheKeyTemplate` 任一变化，都视为旧策略失效 | 策略变更后旧键不再继续使用 |
| 显式清理 | 仅清理命中范围内的服务缓存，不影响其他服务 | 指定服务清理后首次请求重新执行 |
| 关键上下文变化 | `contextKeys` 覆盖字段值变化时，必须形成新缓存键或视为隔离未命中 | 同参数不同 `tenantId`/`callerId` 不得复用 |

补充约束：

- 当前最小闭环已完成 `TTL` 自然失效、版本命名空间隔离、停用联动关闭策略、策略变更导致旧键不再复用，以及按服务的显式清理接口
- 显式清理通过管理接口 `DELETE /api/admin/services/{id}/cache-policy/cache` 触发，只清理当前服务的进程内缓存键前缀 `data-service:{serviceCode}:`
- 被显式清理的缓存键在下一次查询未命中时回写 `cacheMissReason=EXPLICIT_EVICT`，便于调用方区分普通未命中与人工清理

缓存可观测信息：

| 字段 | 含义 | 触发时机 |
| --- | --- | --- |
| `cacheHit` | 是否命中缓存 | 查询响应元信息、日志、审计摘要 |
| `cacheKeyTemplate` | 当前命中的模板或策略模板 | 调试日志、诊断信息 |
| `cacheNamespaceVersion` | 缓存所属服务版本 | 响应元信息、日志 |
| `cacheMissReason` | 未命中原因，如 `MISS`、`TTL_EXPIRED`、`POLICY_DISABLED`、`VERSION_CHANGED`、`CONTEXT_CHANGED`、`EXPLICIT_EVICT` | 未命中时记录 |
| `cacheIsolationReason` | 因关键上下文隔离未复用的原因摘要 | `contextKeys` 命中差异时记录 |
| `cacheWriteSkippedReason` | 未写缓存原因，如执行失败、服务停用、策略关闭 | 回填阶段记录 |

观测约束：

- 响应元信息至少要能区分 `cacheHit=true/false` 和当前服务版本
- 日志或审计摘要必须能区分普通未命中、TTL 失效、策略关闭、版本切换、上下文隔离
- 当前阶段即使运行时缓存模块未完全落地，也必须按上述字段命名保持口径一致，避免后续实现漂移

### 5.7 权限与审计模块

职责：

- 控制管理接口与查询接口访问边界
- 记录保存、发布、停用、测试连接、校验、执行等关键事件
- 提供审计检索能力

处理规则：

- 调用方只允许访问统一查询接口
- 当前最小闭环查询接口要求调用方显式提供 `callerId`，用于最小认证、审计和问题追踪
- 管理接口必须独立鉴权
- 当前最小闭环管理接口统一要求 `X-Operator` + `X-Operator-Role=ADMIN`；连接、服务、发布、停用、预览和缓存策略接口共用同一套 `AdminAccessFilter`
- 管理接口权限失败统一返回 `403 ACCESS_DENIED`，并写入 `ADMIN_ACCESS_DENIED` 审计事件；当前最小闭环按 URI 归类 `CONNECTION` / `SERVICE` 目标类型
- 审计日志必须记录 SQL 版本、解析结果摘要、校验结果摘要、执行摘要和调用上下文摘要
- SQL 预览执行必须纳入独立权限控制和审计记录
- 涉及敏感字段必须脱敏

审计检索模型：

| 维度 | 当前口径 | 说明 |
| --- | --- | --- |
| 列表接口 | `GET /api/admin/audits` | 管理端统一审计检索入口 |
| 详情接口 | `GET /api/admin/audits/{id}` | 查看单条审计完整内容 |
| 筛选条件 | `serviceCode` / `operator` / `eventType` / `operationResult` / `traceId` / `startAt` / `endAt` | 满足需求中的服务、用户、时间、事件和结果维度 |
| 分页 | `page` / `size` | 默认 `page=1`、`size=20`，`size` 最大 200 |
| 排序 | `created_at desc, id desc` | 与审计页默认倒序展示保持一致 |
| 脱敏 | `detailJson` / `contextSummaryJson` 对 `password`、`passwordCiphertext`、`credential`、`secret`、`token` 等敏感键统一替换为 `***` | 审计检索不泄露敏感明文 |

补充约束：

- 列表接口返回摘要字段，不直接展开 `detailJson` 与 `contextSummaryJson`
- 当前最小闭环统一通过 `AuditSensitiveDataMasker` 处理审计写入和审计读取，避免仅在详情返回时兜底脱敏
- 详情接口保留原始 JSON 结构，但在返回前继续复用同一脱敏规则做键级脱敏
- `serviceCode` 筛选先解析为 `serviceId` 再查询 `DS_AUDIT_LOG`，避免在审计表冗余保存服务编码副本
- `tenantId`、`callerId`、`traceId`、`serviceCode`、`eventType` 允许以摘要形式保留；查询输入参数当前只记录参数键名，不记录参数值
- 当 `detailJson` / `contextSummaryJson` 不是合法 JSON 且文本命中 `password`、`credential`、`secret`、`token`、`ciphertext` 等敏感词时，统一整体替换为 `***`

## 6. 核心数据模型设计

### 6.1 删除的表

| 表 | 删除原因 |
| --- | --- |
| `DS_CATALOG` | 目标库不再独立维护，schema/database 必须写在 SQL 全限定名中 |
| `DS_SOURCE` | 来源定义从 SQL AST 自动解析，不再由表单录入 |
| `DS_FIELD` | 返回字段从 SQL `select` 列表自动解析，不再由表单录入 |
| `DS_PARAM` | 参数从 SQL 模板占位符自动解析，不再由表单录入 |
| `DS_SQL_TEXT` | SQL 原文并入服务版本快照，不再单独维护 |
| `DS_SQL_PLAN` | 旧计划表删除，计划快照并入服务版本或按新结构重建 |
| `DS_SQL_VALIDATE_LOG` | 旧校验日志删除，校验快照并入服务版本或按新结构重建 |

### 6.2 保留的表

| 表 | 保留内容 | 调整说明 |
| --- | --- | --- |
| `DS_CONNECTION` | 连接编码、连接名称、数据库类型、主机、端口、用户名、密码密文、扩展配置、状态、审计字段、删除字段 | 只负责连通性 |
| `DS_SERVICE` | 服务编码、服务名称、SQL 类型、状态、当前版本、资源限制、审计字段、删除字段、租户相关预留字段 | 不再直接保存来源、字段、参数配置 |
| `DS_SERVICE_VERSION` | 版本号、SQL 原文、来源快照、参数快照、字段快照、校验快照、计划快照、状态、发布信息、调用上下文预留摘要 | 作为运行时唯一配置快照来源 |
| `DS_CACHE_POLICY` | 缓存开关、TTL、缓存键策略、上下文隔离策略 | 服务级缓存配置 |
| `DS_SOURCE_CAPABILITY` | 数据源能力配置 | 联邦 SQL 下推、方言、执行策略判断 |
| `DS_DIALECT_RULE` | 数据库方言规则 | SQL 重写和方言适配 |
| `DS_AUDIT_LOG` | 管理、保存、发布、查询、校验、执行审计、调用上下文摘要 | 保留 |

基础枚举与预置数据规则：

- `DS_DIALECT_RULE` 允许预置 `db_type` 级默认规则，作为方言适配的最小基线
- 当前阶段默认预置 `POSTGRESQL`、`MYSQL`、`ORACLE` 的 `STRING_CONCAT`、`CURRENT_TIMESTAMP` 规则
- 连接级方言规则仍允许覆盖数据库类型级默认规则
- `DS_SOURCE_CAPABILITY` 当前不做全局预置，因为其最小作用域是具体 `connection_id`，必须绑定真实连接后再维护
- 联邦发布阶段对能力数据的最小闭环仍是“连接下至少存在一条启用能力记录”

### 6.4 `DS_SERVICE_VERSION` 最小字段

| 字段 | 说明 |

| `id` | 主键 |
| `service_id` | 关联 `DS_SERVICE.id` |
| `version` | 服务版本号 |
| `status` | `DRAFT` / `PUBLISHED` / `DISABLED` |
| `sql_type` | `SIMPLE_SQL` / `FEDERATED_SQL` |
| `sql_text` | 用户保存的 SQL 原文 |
| `source_snapshot_json` | 保存时从 SQL 解析出的来源快照 |
| `param_snapshot_json` | 保存时从 SQL 解析出的参数快照 |
| `field_snapshot_json` | 保存时从 SQL 解析出的字段快照 |
| `validation_snapshot_json` | 保存或发布时的校验结果快照 |
| `plan_snapshot_json` | 发布时生成的执行计划快照 |
| `request_context_snapshot_json` | 运行与审计所需的调用上下文预留摘要 |
| `published_at` / `published_by` | 发布审计字段 |
| `created_at` / `created_by` | 创建审计字段 |
| `updated_at` / `updated_by` | 更新审计字段 |

### 6.5 快照结构

`source_snapshot_json`：

| 字段 | 说明 |
| --- | --- |
| `connectionCode` | SQL 中显式引用的连接编码；简单 SQL 来自默认连接 |
| `schemaName` | SQL 中显式引用的 schema 名称 |
| `databaseName` | SQL 中显式引用的 database 名称 |
| `tableName` | SQL 中显式引用的表名 |
| `alias` | SQL 表别名 |
| `dbType` | 解析出的连接数据库类型 |

`param_snapshot_json`：

| 字段 | 说明 |
| --- | --- |
| `paramName` | SQL 模板占位符名称 |
| `paramType` | 保存时由用户确认的参数类型 |
| `placeholder` | SQL 模板占位符名称，默认与 `paramName` 一致 |
| `collection` | 是否集合参数 |

`field_snapshot_json`：

| 字段 | 说明 |
| --- | --- |
| `fieldName` | SQL 输出字段名，优先取 `as` 别名 |
| `expression` | 原始 select 表达式 |
| `sortOrder` | 输出顺序 |

`request_context_snapshot_json`：

| 字段 | 说明 |
| --- | --- |
| `tenantId` | 预留的租户标识摘要，用于隔离与审计 |
| `callerId` | 调用方标识摘要 |
| `traceId` | 链路追踪标识摘要 |
| `contextKeys` | 纳入缓存隔离或审计的关键上下文字段名集合 |

调用上下文字段规则：

| 字段 | 当前语义 | 可空规则 |
| --- | --- | --- |
| `tenantId` | 预留的租户标识，用于后续隔离、缓存和审计扩展 | 当前阶段可空；仅在启用租户隔离时转为必填 |
| `callerId` | 调用方标识，用于审计与调用侧追踪 | 当前阶段可空，建议透传 |
| `traceId` | 链路追踪标识，用于问题定位与审计关联 | 当前阶段可空，建议透传 |
| `contextKeys` | 参与缓存隔离或审计摘要的关键上下文字段名 | 当前阶段可空 |

多租户字段预留边界：

- 当前阶段仅在 `DS_SERVICE.tenant_id` 保留租户字段扩展位
- `DS_SERVICE_VERSION`、`DS_AUDIT_LOG`、缓存隔离等场景优先通过调用上下文摘要和快照字段预留租户信息
- 当前不要求所有元数据表立即强制增加 `tenant_id`
- 只有在后续正式租户模型明确后，才统一扩展表结构、唯一约束、索引、查询条件和权限校验

租户上下文校验规则：

- 未启用租户隔离时，`tenantId` 可为空，不作为当前阶段请求失败条件
- 当前最小闭环以 `DS_SERVICE.tenant_id` 是否为空作为租户隔离启用条件；为空表示不启用，非空表示必须按该租户执行查询隔离
- 启用租户隔离时，调用上下文缺失 `tenantId` 必须明确失败
- 启用租户隔离时，`tenantId` 与服务授权租户范围不一致必须明确失败
- 租户上下文校验结果需纳入审计摘要，便于后续责任定位
- 当前最小闭环在正式查询入口写入 `QUERY_TENANT_ACCESS_DENIED` 审计，摘要保留 `requiredTenantId`、`actualTenantId`、`callerId` 和 `traceId`

### 6.6 索引设计

- `DS_CONNECTION(connection_code)` 唯一索引
- `DS_SERVICE(service_code)` 唯一索引
- `DS_SERVICE_VERSION(service_id, version)` 唯一索引
- `DS_AUDIT_LOG(service_id, created_at, id)` 索引
- `DS_AUDIT_LOG(connection_id, created_at, id)` 索引
- `DS_AUDIT_LOG(operator, created_at, id)` 索引
- `DS_AUDIT_LOG(event_type, created_at, id)` 索引
- `DS_AUDIT_LOG(operation_result, created_at, id)` 索引
- `DS_AUDIT_LOG(trace_id)` 索引
- `DS_SOURCE_CAPABILITY(connection_id, capability_code)` 索引
- `DS_DIALECT_RULE(connection_id, rule_code)` 索引

索引审查结论：

| 对象 | 结论 | 说明 |
| --- | --- | --- |
| `DS_CONNECTION` | 保留现有唯一索引和状态时间索引 | 满足按编码唯一读取、按状态列表查询 |
| `DS_SERVICE` | 保留 `service_code` 唯一索引、`status+created_at`、`current_version`、`default_connection_code` | 覆盖服务详情、列表、发布版本切换和默认连接筛选 |
| `DS_SERVICE_VERSION` | 保留 `(service_id, version)` 唯一索引、`service_id+version desc`、`service_id+status+version desc` | 覆盖历史版本、最新草稿、当前发布版本查询 |
| `DS_CACHE_POLICY` | 保留 `(service_id, enabled)` 条件索引 | 覆盖按服务加载启用策略；无需额外单列 TTL 索引 |
| `DS_SOURCE_CAPABILITY` | 同时保留唯一索引和状态索引 | 一个用于防重复，一个用于运行期按连接读取启用能力，职责不同，不视为重复索引 |
| `DS_DIALECT_RULE` | 保留连接级与 `db_type` 级状态索引 | 分别覆盖连接定制规则和数据库类型默认规则查询 |
| `DS_AUDIT_LOG` | 保留服务、连接、操作人、事件类型、结果、`trace_id` 多维索引 | 满足审计检索场景，不再额外增加低收益复合索引 |

不新增索引说明：

- 不为 `ttl_seconds`、`enabled`、`status` 单独补全表扫描索引，因为当前查询模式均以业务主键或外键驱动
- 不为 JSON 快照字段建立索引，因为当前阶段只做持久化与展示，不做 JSON 条件检索
- 不为 `remark`、审计详情、上下文摘要等低选择性文本字段建索引，避免写入成本增加

## 7. SQL 语法约束

### 7.1 总体规则

| 规则 | 说明 |
| --- | --- |
| 只允许只读 SQL | 仅允许 `select` / `with` |
| SQL 必须显式表达来源 | 不再通过目标库、来源定义表单补充来源 |
| 参数只能使用模板语法 | 禁止 `:param` 旧语法 |
| `/* */` 只保留给模板语法 | 禁止在 SQL 中写普通块注释 |
| 普通说明不写入 SQL | 业务说明写在服务备注或版本说明中 |
| 字段名以 SQL 输出为准 | 返回字段名优先取 `as` 别名 |

### 7.2 简单 SQL 语法

简单 SQL 必须使用数据库内部全限定名。

PostgreSQL：

```sql
select
  o.customer_id as customerId,
  o.order_amount as orderAmount
from public.customer_order o
where o.customer_id = /* customerId */0
```

MySQL：

```sql
select
  c.customer_id as customerId,
  c.customer_name as customerName
from crm.customer c
where c.customer_id = /* customerId */0
```

Oracle：

```sql
select
  e.employee_id as employeeId,
  e.employee_name as employeeName
from HR.employee e
where e.employee_id = /* employeeId */0
```

规则：

| 项 | 规则 |
| --- | --- |
| 连接 | 保存服务时选择一个默认连接，SQL 内不写连接名前缀 |
| schema/database | 必须在表名前显式写出 |
| 表 | 必须可通过默认连接真实访问 |
| 参数 | 从 `/* paramName */默认值` 自动解析 |
| 字段 | 从 `select` 列表自动解析，建议所有输出列显式 `as` |

### 7.3 联邦 SQL 语法

联邦 SQL 使用平台 DSL：

```text
connection_code@schema_or_database.table_name
```

示例：

```sql
select
  c.customer_id as customerId,
  c.customer_name as customerName,
  o.total_amount as totalAmount
from pg_trade@public.customer c
join mysql_billing@crm.order_summary o
  on c.customer_id = o.customer_id
where c.customer_id = /* customerId */0
```

规则：

| 项 | 规则 |
| --- | --- |
| 连接 | `@` 左侧必须是已存在且启用的 `connection_code` |
| schema/database | `@` 右侧第一段必须显式写出 schema 或 database |
| 表 | 第二段必须是表名 |
| 别名 | 多表 SQL 必须显式写别名 |
| Join | Join 条件必须可被解析器识别 |
| CTE / 子查询 / union | 必须纳入解析器支持范围，来源解析递归深入子查询、CTE 与 union 分支 |
| 参数 | 从 SQL 模板占位符自动解析 |
| 字段 | 从最终输出 `select` 列表解析，不做业务语义推断 |

### 7.4 参数模板语法

必填参数：

```sql
where customer_id = /* customerId */0
```

非必填参数：

```sql
where 1 = 1
/*%if customerId != null */
  and customer_id = /* customerId */0
/*%end*/
```

### 7.5 复杂表达式支持清单

| 类别 | 支持项 | 当前口径 |
| --- | --- | --- |
| 条件表达式 | `CASE WHEN ... THEN ... ELSE ... END` | 属于正式支持范围，保存、预览、发布、运行阶段使用一致约束口径 |
| 类型转换 | `CAST(...)` 及等价数据库类型转换表达式 | 属于正式支持范围，无法兼容时必须在保存、预览或发布阶段明确失败 |
| 日期时间 | 日期取值、时间取值、日期时间运算与格式化相关表达式 | 属于正式支持范围，按数据源方言规则适配或明确失败 |
| 字符串 | 拼接、截取、去空格、大小写转换等字符串处理表达式 | 属于正式支持范围，按方言规则适配或明确失败 |
| 聚合 | `COUNT`、`SUM`、`AVG`、`MIN`、`MAX` 等聚合表达式 | 属于正式支持范围，需与过滤、排序、投影、关联规则一起校验 |
| 函数表达式 | 常见数据库函数及平台可映射函数 | 属于正式支持范围，依赖 `DS_DIALECT_RULE` 做方言适配或失败提示 |
| 查询结构 | CTE、子查询、`UNION`、`UNION ALL` | 必须纳入解析器支持范围，来源解析递归深入各层级分支 |
| 输出约束 | 复杂表达式出现在 `select` 列表 | 必须显式使用 `as` 别名，否则保存失败 |

### 7.6 SQL 结构支持清单

| 结构类别 | 支持项 | 当前口径 |
| --- | --- | --- |
| 公共表表达式 | `WITH ... AS (...)` | 属于正式支持范围，来源解析必须递归深入 CTE 内部 |
| 子查询 | `exists (...)`、内层 `select`、派生表 | 属于正式支持范围，来源解析必须递归深入子查询 |
| 集合运算 | `UNION`、`UNION ALL` | 属于正式支持范围，来源与字段解析必须覆盖各分支 |
| 多表关联 | `JOIN` 及其 `ON` 条件 | 属于正式支持范围，Join 条件必须可被解析器识别 |
| 多表别名 | 多表查询中的表别名 | 多表 SQL 必须显式写表别名，否则保存失败 |
| 输出别名 | 复杂表达式或聚合输出列别名 | 必须显式使用 `as` 别名，否则保存失败 |

### 7.7 方言失败口径清单

| 失败类别 | 典型场景 | 当前口径 |
| --- | --- | --- |
| 方言不兼容 | `CAST`、日期时间、字符串或函数表达式无法映射到目标数据源 | 必须在保存、预览或发布阶段明确失败，不得模糊返回 |
| 联邦能力不足 | 下推能力缺失、联邦能力配置缺失、本地补算无法保证语义一致 | 必须明确定位到能力边界或下推限制，不得静默降级 |
| SQL 结构不合法 | 多表查询缺别名、复杂表达式缺 `as`、多语句、危险函数、非只读语句 | 必须在保存阶段直接失败 |
| 对象不存在 | 连接不存在或未启用，schema/database/table 不存在 | 必须返回对象级定位信息 |
| 参数或快照不一致 | 参数类型未确认、预览参数类型不匹配、草稿快照与重解析结果不一致 | 必须返回校验失败，不得进入发布或执行 |
| 数据源执行失败 | 连接测试失败、预览执行 JDBC 失败、运行阶段远端查询失败 | 必须归类为数据源错误或执行错误，并保留失败原因摘要 |
| 资源保护触发 | 结果集上限、批量上限、超时、受控并发或内存保护触发 | 必须受控失败，并返回明确错误类别与原因说明 |

### 7.8 数据库组合矩阵

| 场景 | 组合类型 | 当前口径 |
| --- | --- | --- |
| 单源查询 | Oracle / Oracle | 正式支持 |
| 单源查询 | MySQL / MySQL | 正式支持 |
| 单源查询 | PostgreSQL / PostgreSQL | 正式支持 |
| 同构联邦 | Oracle / Oracle | 正式支持 |
| 同构联邦 | MySQL / MySQL | 正式支持 |
| 同构联邦 | PostgreSQL / PostgreSQL | 正式支持 |
| 异构联邦 | Oracle / MySQL | 正式支持，不作为后续扩展能力处理 |
| 异构联邦 | Oracle / PostgreSQL | 正式支持，不作为后续扩展能力处理 |
| 异构联邦 | MySQL / PostgreSQL | 正式支持，不作为后续扩展能力处理 |

### 7.9 联邦能力矩阵

| 能力项 | 当前口径 | 元数据承载 |
| --- | --- | --- |
| 过滤下推 | 正式支持，依据数据源能力决定是否允许下推 | `DS_SOURCE_CAPABILITY` |
| 投影下推 | 正式支持，依据数据源能力决定是否允许下推 | `DS_SOURCE_CAPABILITY` |
| Join 调整 | 正式支持 `Join Reorder` 优化 | `DS_SOURCE_CAPABILITY` + 执行计划 |
| 排序下推 | 正式支持，依据数据源能力与语义一致性决定是否下推 | `DS_SOURCE_CAPABILITY` |
| 聚合下推 | 正式支持，需与函数、排序、过滤规则一起校验 | `DS_SOURCE_CAPABILITY` |
| 函数下推 | 正式支持，依赖 `DS_DIALECT_RULE` 与能力配置共同判定 | `DS_SOURCE_CAPABILITY` + `DS_DIALECT_RULE` |
| 本地补算 | 仅在保持语义一致时允许；无法保证语义一致时必须明确失败 | 执行计划 + 失败口径 |

### 7.10 本地补算边界清单

| 场景 | 当前口径 |
| --- | --- |
| 下推能力缺失但平台可按已发布快照在本地完成等价整合 | 允许本地补算 |
| 本地补算会改变过滤、聚合、排序、函数或类型转换语义 | 禁止补算，必须明确失败 |
| 方言差异可通过规则重写后保持语义一致 | 允许先适配再执行，不视为静默降级 |
| 方言差异无法通过规则重写保持语义一致 | 必须明确失败 |
| 本地整合触发结果集、内存、超时等资源保护阈值 | 必须受控失败，不继续补算 |
| 仅为了掩盖能力配置缺失或下推限制而做后处理 | 明确禁止，必须按能力不足失败处理 |

集合参数：

```sql
where customer_id in /* customerIds */(0)
```

规则：

| 项 | 规则 |
| --- | --- |
| 参数名 | 从占位符自动解析 |
| 参数类型 | 保存服务时由用户确认 |
| 是否必填 | 不单独维护，靠 SQL 是否处于动态条件块表达 |
| 默认值 | 优先写在模板占位符后的示例字面量中 |
| 格式 | 日期、时间等格式由参数类型和调用协议约定 |

## 8. 后端实现设计

### 8.1 分层与目录职责

| 模块或包路径 | 主要职责 |
| --- | --- |
| `data-service-app` | Spring Boot 启动与运行期装配 |
| `data-service-core.error / config / meta.web.support` | 公共异常、配置、上下文支撑 |
| `data-service-core.web` | HTTP 接入层 |
| `data-service-core.datasource` | 连接管理与 JDBC URL 构造 |
| `data-service-core.service` | 服务保存、发布、版本切换、快照管理 |
| `data-service-core.query` | 统一查询编排 |
| `data-service-core.query.executor` | SQL 模板渲染、参数绑定、只读校验、结果映射 |
| `data-service-core.query.cache` | 查询缓存支撑 |
| `data-service-core.query.protection` | 资源保护支撑 |
| `data-service-core.federation` | 联邦 SQL 解析、校验、规划、执行、方言、能力 |
| `data-service-core.audit` | 审计写入与审计检索 |
| `data-service-core.security` | 权限与平台访问控制 |
| `data-service-core.repository` | 元数据库访问 |

### 8.2 连接管理设计

处理逻辑：

1. 根据 `connectionCode` 读取连接配置
2. 根据 `dbType` 选择驱动
3. 初始化或复用连接池
4. 执行 JDBC 连通性测试
5. 提供运行时连接访问能力

### 8.3 服务保存设计

处理逻辑：

1. 接收服务基本信息、SQL 类型、SQL 文本
2. 简单 SQL 读取默认连接；联邦 SQL 从 SQL 本文解析连接
3. 解析 SQL AST
4. 抽取来源、参数、字段
5. 校验连接、schema/database、table 是否真实存在
6. 前端确认参数类型
7. 生成草稿快照并写入 `DS_SERVICE_VERSION`
8. 预留调用上下文摘要字段，用于后续租户隔离、缓存隔离和审计扩展

### 8.4 服务发布设计

处理逻辑：

1. 读取草稿版本 SQL 和快照
2. 重新解析 SQL，确认 SQL 与快照一致
3. 执行只读校验、对象存在性校验、权限校验、能力校验
4. 生成逻辑计划、优化计划和执行计划
5. 写入校验快照和计划快照
6. 切换服务为已发布版本
7. 记录审计日志

### 8.5 查询执行设计

处理逻辑：

1. 根据 `serviceCode` 加载 `PUBLISHED` 服务
2. 读取当前发布版本快照
3. 标准化调用上下文并校验租户、调用方和链路追踪等关键字段
4. 根据 `param_snapshot_json` 校验和转换请求参数
5. 根据 `plan_snapshot_json` 决定单源执行、远端下推或本地整合
6. 根据 `source_snapshot_json` 获取连接并生成目标数据库 SQL
7. 结合服务版本、请求参数和关键调用上下文生成缓存键并应用缓存
8. 执行 SQL
9. 根据 `field_snapshot_json` 组装统一响应
10. 记录缓存、日志和审计摘要

正式查询审计模型：

| 字段 | 当前口径 | 说明 |
| --- | --- | --- |
| `eventType` | `QUERY_EXECUTE` | 正式查询统一使用单一事件类型，靠结果与摘要区分成功失败 |
| `operationResult` | `SUCCESS` / `FAILURE` | 全成功记为 `SUCCESS`；入口异常、鉴权失败或响应级失败记为 `FAILURE` |
| `detailJson` | `serviceCode` / `serviceVersion` / `queryStatus` / `elapsedMs` / `requestedBatchSize` / `inputParamKeys` / `successCount` / `failureCount` / `cacheHit` / `itemSummaries[]` / `errorCode` / `errorMessage` / `diagnosticSummary` | 统一承载正式查询执行摘要 |
| `contextSummaryJson` | `traceId` / `callerId` / `tenantId` / `contextKeys` / `contextSummaryKeys` / `requestedBatchSize` / `inputParamKeys` / `cacheHit` / `queryStatus` / `errorCode` | 统一承载上下文、缓存和错误摘要 |

补充约束：

- 正式查询审计在统一查询入口落库，成功与失败都用独立事务写入，避免主链路异常时丢失审计
- 单项失败但整体仍返回 `FAILURE` 或 `PARTIAL_FAILURE` 时，`detailJson.itemSummaries[]` 必须能定位每个输入项的状态、行数、缓存命中和失败阶段
- 资源保护失败场景需把 `diagnosticSummary` 原样带入查询审计，避免审计口径与接口响应漂移

### 8.6 发布校验设计

发布前必须完成以下校验：

- `DS_SERVICE` 基本信息完整
- SQL 语法合法
- SQL 只读合法
- 连接存在且启用
- SQL 中引用的 schema、database、table 真实存在
- 参数快照完整且参数类型已确认
- 字段快照完整且复杂表达式均有别名
- 复杂表达式、异构方言和联邦能力边界已完成一致性校验
- 联邦 SQL 已通过能力校验
- 联邦 SQL 已生成执行计划
- 资源限制配置完整

## 10. 核心流程

### 10.1 数据源配置流程

1. 提交连接信息
2. 校验唯一性与必填项
3. 执行连接测试
4. 保存 `DS_CONNECTION`

### 10.2 服务保存流程

1. 创建或编辑服务草稿
2. 录入 SQL
3. 解析 SQL
4. 自动识别来源、参数、字段
5. 校验连接和对象存在性
6. 用户确认参数类型
7. 保存 `DS_SERVICE`
8. 保存一条 `DS_SERVICE_VERSION(status=DRAFT)`

### 10.3 服务发布流程

1. 读取草稿版本
2. 重新解析 SQL
3. 执行发布校验
4. 生成执行计划
5. 写入校验快照和计划快照
6. 切换服务为 `PUBLISHED`
7. 记录发布审计

### 10.4 SQL 预览执行流程

1. 接收草稿 SQL、预览参数和调用上下文
2. 执行权限校验、只读校验和资源保护校验
3. 解析 SQL 并生成来源、参数、字段快照
4. 校验连接、对象存在性、复杂表达式、异构方言和联邦能力边界
5. 生成预览执行计划
6. 执行受控只读查询
7. 返回预览结果、执行耗时和关键诊断摘要
8. 记录预览执行审计，不生成正式服务版本

预览执行响应结构：

| 字段 | 说明 |
| --- | --- |
| `serviceId` | 当前服务主键 |
| `draftVersion` | 当前预览对应的草稿版本号 |
| `previewParams` | 本次预览使用的参数集合 |
| `requestContext` | 本次预览使用的调用上下文摘要 |
| `planSnapshotJson` | 本次预览生成的计划快照 |
| `rows` | 预览结果数据 |
| `elapsedMs` | 预览执行耗时 |
| `diagnosticSummary` | 关键诊断摘要，如结果条数、截断信息等 |

失败口径：

- 失败原因通过统一错误响应返回，错误类别需能区分参数错误、校验错误、数据源错误和资源保护错误
- 失败详情需同时写入预览执行审计，保留错误原因摘要

预览执行限制：

- 仅允许受控只读查询，禁止通过预览绕过正式查询安全边界
- 必须应用结果集上限、超时和资源保护限制
- 不生成正式发布版本，不切换当前发布版本
- 当前阶段真执行仅开放 `SIMPLE_SQL`
- 当前阶段真执行暂不支持 Doma 条件块

### 10.5 查询执行流程

1. 接收统一查询请求
2. 加载已发布服务和当前版本快照
3. 标准化调用上下文并校验租户、调用方和链路追踪等关键字段
4. 绑定请求参数
5. 根据服务版本、请求参数和关键调用上下文生成缓存键并应用缓存
6. 执行单源或联邦查询
7. 组装响应
8. 记录日志和审计摘要

补充约束：

- 查询入口在标准化调用上下文后即开始计时，入口鉴权失败、租户校验失败、批量保护失败和服务未发布都必须写 `QUERY_EXECUTE` 审计
- `QUERY_TENANT_ACCESS_DENIED` 继续作为租户越权专项审计；正式查询总审计不替代该专项事件
- 当前最小闭环统一由 `QueryAuditSummaryService` 生成正式查询 `detailJson` 与 `contextSummaryJson`，保证成功、失败和租户专项审计的摘要字段口径一致
- 审计写入前统一经过 `AuditSensitiveDataMasker`，保证正式查询、租户拒绝、连接管理和管理权限拒绝等场景不把敏感值以明文落库

## 11. 接口设计

### 11.1 查询接口

- `POST /api/data-services/query`

用途：

- 执行单次查询和批量查询

### 11.2 管理接口

- `POST /api/admin/connections`
- `PUT /api/admin/connections/{id}`
- `POST /api/admin/connections/{id}/test`
- `PUT /api/admin/connections/{id}/status`
- `POST /api/admin/services`
- `PUT /api/admin/services/{id}`
- `POST /api/admin/services/{id}/preview`
- `POST /api/admin/services/{id}/publish`
- `PUT /api/admin/services/{id}/status`
- `GET /api/admin/services/{id}/cache-policy`
- `PUT /api/admin/services/{id}/cache-policy`
- `GET /api/admin/audit-logs`
- `GET /api/admin/audit-logs/{id}`

接口要求：

- 管理接口与查询接口分离
- 错误码统一
- 管理接口必须鉴权
- 保存服务时自动解析 SQL
- 预览执行接口必须独立鉴权，并复用正式执行链路中的只读校验、资源保护和审计能力
- 不再提供目标库、来源、字段、参数单独维护接口

缓存策略管理最小闭环：

| 维度 | 当前口径 | 说明 |
| --- | --- | --- |
| 读写模型 | `enabled + ttlSeconds + cacheKeyTemplate + maxEntries + contextKeys + remark` | 与 `DS_CACHE_POLICY` 一一对应，便于前端直接配置 |
| 管理接口 | `GET/PUT /api/admin/services/{id}/cache-policy` | 独立于服务基础信息接口，避免把缓存配置混入保存/发布请求 |
| 默认口径 | 未配置策略时返回 `enabled=false` 与默认模板 | 默认模板使用 `data-service:{serviceCode}:v{version}:{paramHash}` |
| 运行时加载 | `QueryCachePolicyLoader` | 查询执行前统一读取策略快照，未配置或已关闭时按禁用策略处理 |

补充约束：

- 当 `enabled=true` 时必须显式提供 `ttlSeconds`，禁止依赖运行时隐式默认值
- `contextKeys` 必须先做去空白、去重与稳定排序保留，再写入 `DS_CACHE_POLICY.context_keys_json`

缓存键标准化与诊断模型：

| 维度 | 当前口径 | 说明 |
| --- | --- | --- |
| 参数标准化 | 参数名按字典序输出 JSON，列表顺序原样保留 | 相同语义输入必须生成稳定 `paramHash` |
| 上下文摘要 | 当前仅支持 `tenantId` / `callerId` / `traceId` | `contextKeys` 只允许声明当前标准化上下文字段 |
| 摘要字段 | `paramHash + contextDigest + cacheKey + cacheMissReason + cacheIsolationReason` | 先作为诊断摘要输出，为后续真实缓存读写对齐字段名 |
| 命中口径 | 已接入进程内最小缓存闭环 | 首次查询返回 `cacheHit=false`，重复查询命中时返回 `cacheHit=true` |

补充约束：

- `cacheKeyTemplate` 使用 `{contextDigest}` 时必须同时声明非空 `contextKeys`
- 当前阶段不在响应中暴露原始参数值与上下文值，只暴露哈希和原因摘要，避免泄露敏感内容

## 12. 异常与安全设计

### 12.1 配置阶段异常

- 数据源不可连接
- 服务编码重复
- SQL 语法非法
- SQL 非只读
- 连接不存在或未启用
- schema/database/table 不存在
- 参数类型未确认
- 执行计划生成失败

### 12.2 运行阶段异常

- 服务不存在
- 服务未发布
- 参数不合法
- 批量超限
- 查询超时
- 数据源不可用
- 联邦查询执行失败
- 本地整合超限

### 12.3 安全控制

- 连接密码仅保存密文
- 配置展示对敏感字段脱敏
- 动态 SQL 禁止字符串拼接执行
- 联邦 SQL 必须由系统统一解析与执行
- 查询接口禁止非查询语句
- 管理接口与查询接口路由隔离

## 13. 性能设计

- 连接池按数据源复用
- 高频服务启用本地缓存
- 单批次查询上限必须可配置
- 单次查询结果上限必须可配置
- 单次查询与联邦查询超时必须可配置
- `serviceCode`、`connectionCode`、外键字段必须建立索引
- 联邦 SQL 执行优先减少跨源数据搬运
- 远端执行并发度必须可控
- 中间结果应支持流式处理与必要时落盘
- 本地补算必须具备内存上限和结果集上限保护
- 所有默认参数必须适配单机 4 核 CPU、16G 内存
