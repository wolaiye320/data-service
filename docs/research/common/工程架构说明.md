# 数据服务工程架构说明

## 1. 文档目的

本文档基于《[数据服务需求规格书](/Volumes/osdisk/java_code/data-service/docs/research/common/数据服务-需求规格书.md)》与《[数据服务架构与详细设计](/Volumes/osdisk/java_code/data-service/docs/research/common/数据服务架构与详细设计.md)》编写，用于定义 `data-service` 当前正式采用的工程骨架、模块边界、包结构、依赖方向、构建入口与回归口径。

| 项目 | 说明 |
| --- | --- |
| 适用范围 | 后端模块、前端管理端、元数据库迁移、回归脚本、构建入口 |
| 主目标 | 让代码、文档、脚本、测试命令对同一套工程结构达成一致 |
| 不负责 | 业务规则细节、字段语义、接口契约细节，这些由需求与详细设计文档负责 |

## 2. 设计依据与硬约束

| 类别 | 约束 |
| --- | --- |
| 产品边界 | 系统只提供查询能力，不提供写入业务数据能力 |
| 技术基线 | Java 21、Spring Boot 3.x、MyBatis 注解式 Repository、Flyway、Testcontainers |
| 部署基线 | 单机独立部署，默认资源基线为 4 核 CPU、16G 内存 |
| 数据边界 | 元数据走系统元数据库；业务查询走外部业务库；不得混用 |
| 安全边界 | 查询必须满足只读校验、参数绑定、权限校验、资源保护、审计留痕 |
| 结构原则 | 不再保留 `interfaces/application/domain/infrastructure/federation` 多 Maven 业务模块拆分 |

## 3. 工程总体形态

### 3.1 当前正式结构

| 层面 | 形态 |
| --- | --- |
| 后端 | 单仓库、精简多模块：`data-service-app` + `data-service-common` + `data-service-core` |
| 前端 | `data-service-web` 独立管理端工程 |
| 元数据库 | PostgreSQL，随 Flyway 迁移演进 |
| 外部数据源 | PostgreSQL / MySQL / Oracle 等 JDBC 数据源 |



## 4. 顶层模块

### 4.1 模块清单

| 模块名 | 主要职责 |
| --- | --- |
| `data-service-common` | 公共异常、上下文、枚举、工具、公共常量 |
| `data-service-core` | 核心业务能力承载模块，包含 Web 接口、连接管理、服务定义、查询执行、联邦、审计、安全、Repository |
| `data-service-app` | Spring Boot 启动入口、运行装配、配置绑定、Mapper 扫描、启动集成测试 |
| `data-service-web` | 管理端前端工程 |

### 4.2 模块职责边界

| 模块 | 负责 | 不负责 |
| --- | --- | --- |
| `data-service-common` | 公共运行时基础能力 | 业务编排、Repository、Controller |
| `data-service-core` | 所有后端业务代码与测试 | Boot 启动打包 |
| `data-service-app` | 应用启动、Spring Boot 打包、运行期装配 | 业务规则实现、Repository SQL、联邦执行细节 |

### 4.3 模块依赖关系

| 来源模块 | 目标模块 | 说明 |
| --- | --- | --- |
| `data-service-core` | `data-service-common` | 核心业务依赖公共基础能力 |
| `data-service-app` | `data-service-core` | 启动模块聚合核心业务模块 |
| `data-service-app` | `data-service-common` | 启动模块直接使用公共异常、上下文等基础能力 |

依赖方向示意：

```text
data-service-app
  -> data-service-core
  -> data-service-common

data-service-core
  -> data-service-common
```

## 5. `data-service-core` 包结构

### 5.1 包结构总览

| 包路径 | 职责 |
| --- | --- |
| `cn.dtkeys.dataservice.config` | 配置绑定类与配置对象 |
| `cn.dtkeys.dataservice.web` | Controller、DTO、响应模型、Web 过滤器 |
| `cn.dtkeys.dataservice.datasource` | 数据源连接管理与目标库连接构造 |
| `cn.dtkeys.dataservice.datasource.model` | 连接、catalog、来源能力等数据源域模型 |
| `cn.dtkeys.dataservice.service` | 服务定义、发布、版本、平台基线等业务编排 |
| `cn.dtkeys.dataservice.service.model` | 服务定义、字段、参数、SQL 元数据等服务域模型 |
| `cn.dtkeys.dataservice.query` | 统一查询入口、运行时定义装载、查询编排 |
| `cn.dtkeys.dataservice.query.model` | 查询运行时快照模型 |
| `cn.dtkeys.dataservice.query.executor` | 参数绑定、只读校验、SQL 执行、结果映射 |
| `cn.dtkeys.dataservice.query.cache` | 查询缓存与缓存策略解析 |
| `cn.dtkeys.dataservice.query.protection` | 查询资源保护与并发限制 |
| `cn.dtkeys.dataservice.federation` | 联邦 SQL 元数据管理与联邦执行编排 |
| `cn.dtkeys.dataservice.federation.*` | Parser、Validator、Planner、Optimizer、Executor、Diagnostics 等子域 |
| `cn.dtkeys.dataservice.audit` | 审计事件、审计查询、审计写入 |
| `cn.dtkeys.dataservice.audit.model` | 审计日志模型 |
| `cn.dtkeys.dataservice.security` | 权限码、角色、拦截器、权限判断器 |
| `cn.dtkeys.dataservice.repository` | MyBatis Repository 接口 |

### 5.2 结构原则

| 原则 | 说明 |
| --- | --- |
| 业务域优先 | 主包以 `datasource/service/query/federation/audit/security` 划分 |
| 技术边界最小化 | 仅保留 `web/config/repository/common` 这类必要技术边界 |
| 不保留历史分层壳 | 不再使用 `interfaces/application/domain/infrastructure` 作为主包层级 |
| `federation` 独立保留 | 联邦能力是明确业务域，不是临时技术实现细节 |

## 6. 分层与调用规则

### 6.1 逻辑分层

| 层 | 典型包 | 职责 |
| --- | --- | --- |
| Web 接入层 | `web.controller`、`web.dto`、`web.response` | 协议、参数校验、统一响应 |
| 业务编排层 | `datasource`、`service`、`query`、`federation`、`audit` | 业务流程编排与规则执行 |
| 数据访问层 | `repository` | 元数据查询、持久化、统计、校验 SQL |
| 基础支撑层 | `config`、`query.executor`、`query.cache`、`query.protection`、`security` | SQL 执行、缓存、资源保护、权限、配置绑定 |

### 6.2 调用约束

| 调用关系 | 约束 |
| --- | --- |
| `web -> service/query/datasource/federation/audit` | 允许 |
| `web -> repository` | 禁止直接承载页面流程逻辑；仅极少数只读查询接口可经审慎评估后直连 |
| `service/query/federation -> repository` | 允许 |
| `repository -> web/service` | 禁止 |
| `security` | 允许被 Web 与业务编排层共同使用 |
| `query.executor` | 允许被查询编排与联邦执行器复用 |

## 7. 启动与装配

### 7.1 `data-service-app` 约定

| 项目 | 现状 |
| --- | --- |
| 启动类 | `cn.dtkeys.dataservice.app.DataServiceApplication` |
| 组件扫描 | `@SpringBootApplication(scanBasePackages = "cn.dtkeys.dataservice")` |
| Mapper 扫描 | `@MapperScan("cn.dtkeys.dataservice.repository")` |
| 配置绑定 | 统一在 `data-service-app` 中启用 `DataServiceProperties`、`ResourceProtectionProperties`、`PlatformAccessProperties` |
| MVC 拦截器 | `WebMvcConfiguration` 注入 `PlatformPermissionInterceptor` |

### 7.2 资源与迁移

| 项目 | 路径 |
| --- | --- |
| Flyway 迁移脚本 | `data-service-core/src/main/resources/db/migration/` |
| 核心测试资源 | `data-service-core/src/test/resources/` |
| Boot 运行配置 | `data-service-app/src/main/resources/application*.yml` |

## 8. 测试与回归口径

### 8.1 当前后端测试入口

| 目的 | 命令 |
| --- | --- |
| 核心模块测试 | `mvn -pl data-service-core -am test` |
| 核心定向回归 | `mvn -pl data-service-core -am test -Dtest=ConnectionManagementServiceTest,ServiceDefinitionManagementServiceTest,FederatedMetadataManagementServiceTest,FederatedPipelineTest,PredefinedJoinQueryExecutorTest,MetadataRepositoryIntegrationTest,DatasourceConnectionManagerTest,DatasourceConnectionManagerContainerIntegrationTest,QueryParameterBinderTest,QueryResultMapperTest,SqlReadOnlyValidatorTest,ResourceProtectionServiceTest -Dsurefire.failIfNoSpecifiedTests=false` |
| Boot 集成测试 | `mvn -pl data-service-app -am test -Dtest=AdminManagementIntegrationTest,AuditAndPermissionIntegrationTest,PlatformBaseIntegrationTest,QueryControllerIntegrationTest,QueryExecutionComponentsIntegrationTest -Dsurefire.failIfNoSpecifiedTests=false` |
| 全量后端回归 | `mvn test` |

### 8.2 测试边界

| 类型 | 要求 |
| --- | --- |
| Repository 测试 | 必须使用真实数据库或 Testcontainers，验证字段真实存在 |
| 服务编排测试 | 至少覆盖关键规则与异常路径 |
| Boot 集成测试 | 必须验证 HTTP 链路、权限、审计、配置装配 |
| 联邦测试 | 必须覆盖 Parser、Validator、Planner、Optimizer、Executor 与真实跨源执行场景 |

## 10. 分阶段实施口径

| 阶段 | 说明 |
| --- | --- |
| 第一阶段 | `data-service-core` 内启用连接管理、服务定义、统一查询、缓存、权限、审计等基础能力 |
| 第二阶段 | 在同一 `data-service-core` 内继续扩展 `federation` 子域，不再新增独立 Maven 联邦模块 |
| 演进原则 | 继续沿用统一启动模块、统一元数据模型、统一查询入口与统一回归口径 |

## 11. 变更约束

| 约束 | 说明 |
| --- | --- |
| 新增后端能力 | 默认落在 `data-service-core` 对应业务域包内 |
| 新增 Repository | 统一落在 `cn.dtkeys.dataservice.repository` |
| 新增 Flyway | 统一落在 `data-service-core/src/main/resources/db/migration/` |
| 新增后端测试 | 统一落在 `data-service-core/src/test/java` 或 `data-service-app/src/test/java` |
| 脚本与文档 | 不得再新增引用已删除的 `data-service-interfaces`、`data-service-application`、`data-service-domain`、`data-service-infrastructure`、`data-service-federation` 模块名 |

## 12. 结论

| 结论 | 说明 |
| --- | --- |
| 当前后端正式结构 | `data-service-common` + `data-service-core` + `data-service-app` |
| 当前后端正式主包 | 业务域优先，不再使用历史分层壳 |
| 当前联邦能力落位 | `data-service-core` 内的 `cn.dtkeys.dataservice.federation` |
| 当前文档基线 | 后续架构、测试、脚本、评审应统一按本文件执行 |
