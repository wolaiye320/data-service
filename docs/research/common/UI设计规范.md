## 0. 文档适用边界

### 0.1 通用规范优先

- 本文档正文优先描述可复用于多数中后台项目的通用 UI 规范，如布局、表格、表单、抽屉、视觉一致性等。
- 正文避免绑定具体项目名、目录路径、类名前缀、组件文件路径、脚本入口。
- 若某条规则可被抽象为通用工程约束，应优先写成通用要求，而不是直接写某个项目当前实现。

### 0.2 项目特有约定集中收口

- 品牌名、组件落点、CSS 类名前缀、工具函数路径、页面容器类名等项目特有信息，统一集中在文末“项目特有落地约定”。
- 正文引用项目特有实现时，只说明“见项目特有落地约定”，避免在多个章节重复散落。
- 若切换到其他项目复用本文档，应优先复用正文，仅替换“项目特有落地约定”部分。

## 1. 布局架构

### 1.1 整体结构

- **无顶栏布局**：品牌、用户、通知均集成于左侧栏，无独立 Header
- **双栏布局**：左侧固定侧栏 + 右侧主内容区，横向 `flex` 排列
- **布局结构**：

```
┌──────────────────────────────────────────────────────┐
│ 侧栏 (220px)        │ 主内容区 (flex: 1，无间隙)      │
│ ├ 品牌区            │  Content 卡片贴边，无外圆角      │
│ ├ 导航菜单          │  - 内边距 padding: 24px         │
│ └ 底部区            │  - 白色背景 #fff                │
│    ├ 消息 (独占行)   │                                 │
│    └ 用户 (独占行)   │                                 │
└──────────────────────────────────────────────────────┘
```

### 1.2 布局规范

- **主内容区 Layout 全部不留间隙**：主内容区与侧栏、视口右/上/下边缘之间不设 padding，内容卡片（Content）贴满该区域。

| 元素 | 样式 | 说明 |
|------|------|------|
| 根 Layout | `height: 100vh; overflow: hidden; display: flex; flexDirection: row` | 视口定高，仅右侧内容区滚动 |
| 侧栏 | `width: 220px; height: 100vh; position: sticky; top: 0` | 固定宽度、全高，**不随右侧内容滚动** |
| 内容区 Layout | `flex: 1; minWidth: 0; padding: 0` | 占满剩余空间，**四边不留间隙** |
| Content | `flex: 1; minHeight: 0; overflow: auto; border-radius: 0` | **仅此区域可滚动**，无外圆角，与主内容区齐平 |
| 主内容区背景 | `#f0f2f5` | 页面背景灰（侧栏与内容区之间可见） |
| 内容卡片背景 | `#fff` | 白色，无外圆角 |

## 3. 侧栏规范

### 3.1 结构

| 区域 | 内容 | 样式 |
|------|------|------|
| 品牌区 | Logo | `padding: 20px 16px`，底部细线 |
| 导航菜单 | 数据源管理、访问控制、质量规则 | `flex: 1`，可滚动 |
| 底部区 | 消息、用户信息 | 每项独占一行 |

### 3.1.1 信息架构

- **两级信息架构**：一级菜单表示业务域，二级菜单表示具体功能页面。
- **新增功能归位**：新功能优先挂在既有业务域下；仅当形成独立业务域时才新增一级菜单。
- **配置位置统一**：项目内应为侧栏菜单维护统一配置入口，保持 `icon + link` 或 `children` 等结构一致；具体落点见“项目特有落地约定”。
- **图标来源统一**：新增导航图标、功能图标、状态图标、操作图标与品牌图形时，必须优先从项目统一图标入口与品牌入口中选取；禁止在业务页面直接各自引入不同图标实现相同语义。
- **缺失先补库后使用**：若统一图标入口中不存在所需语义图标，应先补充公共图标映射与命名，再在业务页面使用，禁止绕过统一入口临时直连第三方图标包。

### 3.2 菜单项

- **一行一功能**：每个菜单项独占一行
- **高度**：40px
- **圆角**：8px
- **禁止换行**：`white-space: nowrap`
- **内边距**：`0 12px`，`margin: 4px 8px`
- **选中态**：亮蓝背景 `#3b82f6`，白字
- **hover**：背景 `rgba(255,255,255,0.1)`

### 3.3 底部项（消息、用户）

- **消息**：图标 + 文字「消息」，独占一行，带 Badge 角标
- **用户**：头像 + admin / 管理员，独占一行，高度 48px
- **样式**：使用 `.li-sidebar-bottom-item`，与菜单项视觉一致
- **交互**：点击用户区展开下拉（个人中心、系统设置、退出登录）

## 4. 主内容区

### 4.1 内容卡片

- **样式**：白底、无外圆角（主内容区 Layout 全部不留间隙，卡片贴边）
- **padding**：24px（仅内容区内边距）
- **边框/阴影**：可按需使用细边框 `#f0f0f0` 或浅阴影

### 4.1.1 页面容器

- **页面根容器**：页面根元素应有统一页面容器，用于承接页面级布局与间距约束。
- **主内容卡**：页面主卡片应有统一样式约束，建议保持 `min-height: 360px`，减少路由切换或空状态切换时的页面抖动。
- 项目内实际类名、组件或样式入口见“项目特有落地约定”。

### 4.2 页面标题

- 使用 `PageHeader` 或 `Typography.Title level={5}`
- 标题与操作按钮同一行，操作右对齐
- 优先使用 `PageHeader` 组件，保持各页面标题区结构一致。
- `PageHeader` 应保持稳定高度；无论是否存在右侧操作按钮，标题区视觉高度都应一致，避免页面跳动。

### 4.3 表格

- `Table size="small"`
- **斑马纹**：建议使用统一表格样式类或主题变量控制，偶数行 `#fafafa`
- **行 hover**：`#f5f5f5`
- **选中行**：建议使用统一选中行样式类或主题变量控制高亮状态
- **操作列**：统一使用**图标 + Tooltip**，仅图标不配文字，按钮 `type="text"`，保持简洁一致
- **操作列实现约束**：应优先复用统一的操作按钮组件或封装，禁止在业务页面逐个手写不一致的操作按钮
- **可访问性**：纯图标按钮必须提供稳定可访问名称，如 `aria-label` 或等价语义属性，便于键盘操作、读屏与自动化测试
- **例外机制**：若某操作因业务语义、合规或高风险提示必须显示文字，必须在需求或设计文档中显式声明例外原因、适用页面和交互形式
- **列表内文本**：类型、状态等字段使用**普通文本**展示，不使用彩色 Tag/徽标，保持简洁一致

### 4.4 空状态

- 使用 `EmptyState` 组件
- 提供引导文案和操作按钮

### 4.5 表单内联结果摘要

- 用于抽屉或页面表单中的测试连接、模拟校验、预检查、试运行等即时反馈场景。
- **形态要求**：使用紧凑型内联摘要块，放在表单顶部或相关操作按钮下方；禁止使用占高过大的大段 `Alert description` 堆叠正文。
- **信息层级**：第一行只放结论与一句摘要；详细信息使用 2 列以内的紧凑键值项，优先展示 2 到 4 个最关键指标。
- **颜色要求**：成功使用成功色系 `#52c41a / #f6ffed / #b7eb8f`；失败使用错误色系 `#ff4d4f / #fff2f0 / #ffccc7`；正文与辅助文字颜色仍遵循默认文本色，不额外引入自定义综合色。
- **文案要求**：标题使用简洁结论，如“连接校验通过”“连接校验失败”；辅助说明控制在一行内，超长说明放入键值项或补充说明行。
- **交互要求**：可提供右上角“收起”或关闭能力；关闭后不影响表单已填写内容。
- **响应式要求**：桌面端可使用双列紧凑布局；窄屏下自动退化为单列，避免横向挤压。

## 5. Ant Design 主题

### 5.1 组件选型原则

- **优先复用 Ant Design 现成组件**：中后台界面优先使用 Ant Design 提供的 `Table`、`Form`、`Drawer`、`Modal`、`Spin` 等基础组件，不重复自研同类基础组件。
- **主题统一收口**：颜色、圆角、字号、控件高度等视觉基础能力统一通过 Ant Design theme token 管理，避免页面内各自定义一套视觉参数。
- **轻量封装优先**：确需项目级复用时，优先基于 Ant Design 组件做轻量封装，保持 API 与交互习惯一致，避免脱离 antd 生态另起一套组件体系。

### 5.2 组件与样式职责边界

- **Ant Design 负责组件与交互**：表单、表格、抽屉、弹窗、反馈、加载等交互型 UI 以 Ant Design 为主。
- **Tailwind 负责布局与轻量样式**：间距、对齐、响应式布局、局部微调优先使用 Tailwind 或项目 CSS 类名处理。
- **避免侵入式覆盖**：避免大面积覆盖 antd 内部类名或依赖脆弱的 DOM 结构选择器；如需调整，优先使用 theme token、组件 `styles` / `className` 或项目自有包装层。

```ts
theme: {
  token: {
    colorPrimary: '#1677ff',
    colorSuccess: '#52c41a',
    colorWarning: '#faad14',
    colorError: '#ff4d4f',
    colorInfo: '#1677ff',
    borderRadius: 6,
    borderRadiusLG: 8,
    controlHeight: 32,
    controlHeightSM: 24,
    fontSize: 14,
    fontSizeHeading5: 16,
    colorText: 'rgba(0, 0, 0, 0.88)',
    colorTextSecondary: 'rgba(0, 0, 0, 0.65)',
  },
  components: {
    Table: {
      headerBg: '#fafafa',
      headerColor: 'rgba(0, 0, 0, 0.88)',
      rowHoverBg: '#f5f5f5',
    },
    Card: { paddingLG: 16 },
    Modal: { borderRadiusLG: 8 },
  },
}
```

## 6. 数据展示规范

- **日期时间**：所有日期时间栏位展示格式统一为 **年-月-日 时:分:秒**（如 `2026-02-17 15:19:00`），不使用 ISO 原始格式或带毫秒/时区符号（如 `T`、`Z`）。
- **小数**：有小数点的数值（如校验结果中的实际值、期望值等）**默认最多保留 2 位小数**展示。
- **状态展示分场景处理**：列表页中的类型、状态、属性列默认优先使用普通文本展示，减少视觉噪音；详情页、摘要区、结果总览区若需要更强的结构化与状态识别，可保留少量 `Tag`、状态徽标或语义色，不视为违规。禁止的是无节制彩色 `Tag` 堆叠，而不是禁止所有状态样式。
- **状态文本与语义色**：当状态仅用于轻量说明时，可使用默认正文色或辅助文本色；当状态承担明确结果语义或识别职责（如健康、启用、失败、同步状态）时，可使用与语义一致的颜色和 `Tag`。
- **信息提示风格分场景处理**：背景说明、使用引导、静态说明等提示优先使用浅蓝 `info` 风格；结果摘要、校验通过、未发现异常、任务成功等带明确结果语义的提示，可使用 `success` / `warning` / `error` 风格，不必强制统一为 `info`。
- **同页提示一致性**：同一页面内多个说明块、摘要块、状态块的视觉语言应保持一致；若页面已有清晰的结果语义分层，应延续该层级，不为了统一而抹平成功、警告、异常之间的区别。
- 项目内具体格式化工具函数见“项目特有落地约定”。

## 7. 弹窗、抽屉与新页面的选择决策

**核心原则**：除**确认类消息弹框**（如删除二次确认、操作结果提示）外，**禁止使用弹窗 (Modal)**。表单新增、编辑、详情查看等交互应优先使用**抽屉 (Drawer)** 或**新页面**，以提升高级感与操作体验。

### 7.1 确认类消息弹框（唯一允许使用弹窗的场景）

| 交互方式 | 适用场景 |
|----------|----------|
| **确认弹窗 Modal** | 删除二次确认（「确定删除吗？」）、危险操作确认、覆盖提示等**纯确认/提示**场景。 |
| **气泡确认 Popconfirm** | 挂载在按钮上的轻量确认，如列表行内删除，视觉干扰最小。 |
| **消息提示 message / notification** | 操作成功/失败反馈，非阻塞式。 |

上述场景外，**不再使用 Modal 承载表单或复杂内容**。

### 7.2 新增操作 (Create)

| 交互方式 | 适用场景 |
|----------|----------|
| **抽屉 Drawer** | **首选**。表单字段少至中等（约 1–15 个）；需参考列表上下文；侧滑展开，空间充足、层次清晰。 |
| **新页面 Page** | 表单极其复杂（大量字段、分步表单、多文件上传）；需沉浸式填写；需要独立 URL（分享或收藏）。 |

### 7.3 编辑操作 (Update)

**新增与编辑应保持一致**：若新增用抽屉，编辑也用抽屉；若新增用新页面，编辑也用新页面。

### 7.4 删除操作 (Delete)

- **二次确认弹窗** 或 **Popconfirm**：行业标准，点击删除后询问「确定删除吗？」以防误操作。
- 删除**从不使用新页面**。

### 7.5 决策对比表

| 维度 | 确认弹窗（仅确认/提示） | 抽屉 (Drawer) | 新页面 (Page) |
|------|------------------------|---------------|---------------|
| 适用范围 | 仅确认、提示、危险操作 | 表单新增/编辑、详情查看 | 复杂录入、审批、撰写 |
| 数据量 | 无/极少 | 少至中等 | 多、复杂、含子表 |
| 用户专注度 | 低（快速确认） | 中高（侧滑聚焦） | 高（沉浸式） |
| 视觉层次 | 居中浮层 | 侧滑覆盖，更显高级 | 全屏 |

### 7.6 快速决策建议

1. **仅需确认/提示**（删除、覆盖、危险操作）：使用 **Modal 确认弹窗** 或 **Popconfirm**。
2. **表单新增/编辑/详情**：一律使用 **抽屉 (Drawer)** 或 **新页面**，**禁止使用 Modal 承载表单**。
3. **字段少至中等**：首选 **抽屉**。
4. **需半小时以上才能填完、需独立 URL**：使用 **新页面**。

> **避坑**：禁止在抽屉或新页面内再嵌套 Modal 承载表单；仅确认/提示类可嵌套。

## 8. 抽屉与表单紧凑性

- **一屏内完整展示**：抽屉（Drawer）内的表单应在常见分辨率下一屏内完整展示，包含标题、全部表单项及底部「确定」「取消」按钮，避免用户必须滚动才能提交。
- **多字段表单**：
  - 使用**两列布局**（Ant Design `Row` + `Col`，`gutter={16}`，每列 `span={12}`）；需整行展示的字段（如长下拉）使用 `span={24}`。
  - 表单项内控件统一使用 **`size="small"`**（`Input`、`Select` 等），减少垂直占高。
- 应为紧凑表单提供统一样式入口，减少表单项 `margin-bottom`，使纵向更紧凑；项目内具体类名见“项目特有落地约定”。
- **长文本字段**：非必填的长文本（如表达式、备注）优先使用单行 `Input`；确需多行时再使用 `Input.TextArea` 并控制 `rows`，避免占用过多垂直空间。

## 9. 表单与下拉选择易用性

- **优先使用下拉框**：凡栏位存在有限可选集合（枚举、来自接口的列表、关联数据等），应尽量使用 **Select 下拉框** 供用户选择，减少手工输入与错误，提升易用性与使用体验。
- **选项来源**：
  - **固定枚举**（如类型、状态、阈值类型）：使用 `Select` + `options`，选项带 `value` 与 `label`（必要时 label 为「中文说明 (代码)」便于理解）。
  - **依赖接口的列表**（如数据源、库名、表名、列名）：先请求接口获取选项，用 `Select` 展示；支持 `showSearch`、`optionFilterProp="label"` 便于检索；选项为空时可按业务需要回退为 `Input` 并提示「暂无下拉数据，可手动输入」。
- **联动与空状态**：
  - 依赖前序选择时（如先选数据源再选库/表/列），占位符明确引导（如「请先选择数据源」「请选择表名」）；前序未选时可 `disabled` 或仅展示占位说明。
  - 下拉选项过滤需兼容大小写、首尾空格；过滤结果为空时可视情况回退为「展示全量选项」或「允许手动输入」，避免用户无法继续填写。
- **后端配合**：列表类接口（如按数据源查库/表/列）在未传筛选参数时，应返回完整可选集合（例如所有 schema 的表），以便前端能按当前已选库名过滤出表名下拉，保证「选库名后表名可下拉展示该库下所有表」。
