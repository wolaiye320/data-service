# 数据服务-集成测试用例设计

## 1. 文档目的

本文档用于为 `data-service` 生成后端集成测试用例提供统一基线，约束“测什么、怎么拆、至少覆盖哪些场景、如何建立需求追踪”，供研发、测试和 AI Agent 在新增或补齐集成测试时直接引用。

本文档不是执行报告，不记录逐次执行日志；本文仅维护最新测试跟踪结论，执行明细统一写入 `docs/research/common/过程文档/`。

## 2. 编写依据

| 来源 | 用途 |
| --- | --- |
| `docs/research/common/数据服务-需求规格书.md` | 确认功能范围、非功能要求、验收标准和测试口径 |
| `docs/research/common/测试规范.md` | 约束测试分层、真实数据库要求、用例编号和文档维护方式 |
| `docs/research/common/数据服务架构与详细设计.md` | 确认模块边界、状态流转、执行链路和联邦实现约束 |
| `docs/research/common/数据服务-WBS.md` | 对齐阶段划分与交付边界 |

## 3. 适用边界

| 项目 | 说明 |
| --- | --- |
| 适用层级 | Repository 集成测试、Service 集成测试、API 集成测试 |
| 主要目标 | 验证真实数据库、真实 Spring 容器、真实 HTTP 链路下的功能正确性 |
| 不包含 | 纯单元测试、浏览器级页面测试、一次性手工验证记录 |
| 数据库要求 | 涉及 SQL、Repository、连接适配、方言行为时必须连接真实数据库或等价真实实例 |
| 环境边界 | PostgreSQL 为常规回归主基线；MySQL / Oracle 保留真实适配用例基线，其中 Oracle 可独立验证，不进入常规回归命令 |

## 4. 用例生成规则

### 4.1 生成字段

| 字段 | 要求 |
| --- | --- |
| 用例编号 | 采用 `IT-{领域}-{序号}` |
| 测试层次 | 标明 `Repository`、`Service` 或 `API` |
| 需求追踪 | 至少关联一个需求章节和一个测试口径章节 |
| 前置条件 | 必须写清服务状态、连接状态、数据库实例、初始化数据 |
| 输入 | 写明请求体、查询参数、数据库配置或元数据条件 |
| 断言 | 必须同时覆盖状态码 / 异常类型、关键字段、数据库副作用或审计结果 |
| 实际结果 | 用于跟踪最新测试状态，统一写 `未执行 / 通过 / 失败 / 阻塞`，必要时补 1 句说明 |
| 自动化状态 | 统一写 `未自动化 / 部分自动化 / 已自动化` |
| 自动化脚本 | 标明推荐或实际测试类 `类名#方法名` |
| 最近执行时间 | 记录最新一次有证据的执行日期，未执行填 `-` |
| 执行人 | 记录最新一次执行或确认结果的责任人，未知填 `-` |
| 证据/报告 | 记录对应测试报告、上线验证记录或脚本证据，未执行填 `-` |
| 备注/阻塞原因 | 记录阻塞原因、环境约束或补测说明，无则填 `-` |

### 4.2 强制覆盖维度

| 维度 | 最低要求 |
| --- | --- |
| 正常路径 | 每个一级能力至少 1 条主成功链路 |
| 异常路径 | 参数错误、配置错误、状态错误、权限错误至少各有代表场景 |
| 状态流转 | 草稿、发布、停用、启用等状态变化必须测 |
| 审计留痕 | 涉及连接变更、发布、停用、测试连接、预览执行必须测审计 |
| 资源保护 | 结果集上限、批量上限、超时、受控并发必须有受控失败断言 |
| 方言 / 连接适配 | PostgreSQL、MySQL、Oracle 三类连接配置至少各覆盖 1 条真实适配用例 |

### 4.3 测试数据别名建议

| 别名 | 含义 | 用途 |
| --- | --- | --- |
| `pg_conn_main` | PostgreSQL 主连接 | 常规回归主链路 |
| `mysql_conn_main` | MySQL 主连接 | MySQL 适配、异构联邦 |
| `oracle_conn_main` | Oracle 主连接 | Oracle 适配、独立验证 |
| `catalog_public` | PostgreSQL 默认目标库 / schema | 基础服务配置 |
| `service_query_demo` | 基础统一查询服务 | API 主链路 |
| `service_batch_demo` | 批量查询服务 | 批量与缓存 |
| `service_federation_demo` | 联邦 SQL 服务 | 联邦校验、发布、执行 |
| `service_cross_source_demo` | 第一阶段预定义跨源服务 | 第一阶段跨源整合 |
