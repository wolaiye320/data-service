# 前端开发规范

## 0. 文档适用边界

- 正文避免直接绑定具体项目目录、脚本命令、组件路径、类名前缀。
- 项目特有命令、落地路径、迁移中的现状说明，统一放在文末“项目特有落地约定”。

### 0.2 项目特有约定集中收口

- 其他项目复用本文档时，应优先复用正文，仅替换项目特有附录。

## React + Ant Design 常见问题与最佳实践

### 0. 根节点与样式实现约定

#### 0.1 Ant Design 根节点配置

- 应用根节点统一使用 `ConfigProvider` 管理主题、组件 token 与中文 locale，避免页面内重复注入或局部各自配置。
- 主题相关配置应集中收口，避免在业务页面中散落硬编码主题参数。

#### 0.2 样式与 antd 的配合方式

- Ant Design 负责基础组件与交互，项目 CSS 类与少量内联样式负责布局、间距、对齐和轻量样式微调。
- 避免通过覆盖 antd 深层内部类名实现主要样式，优先使用组件自身 API、theme token、`styles`、`className` 或项目包装组件。
- 若存在动态 class 合并场景，应统一使用稳定方式处理，避免条件类名拼接混乱或样式冲突。
- 优先使用 token、`gap`、`Space`、栅格和项目已有样式类，避免随意堆叠一次性样式值。

### 1. Form.Item 与表单控件的正确使用

**问题**: 当 Input 等表单控件被 `Space.Compact` 等容器组件包裹时,`Form.Item` 无法自动注入 `value` 和 `onChange` 属性,导致表单值无法正确显示和更新。

**错误示例**:
```tsx
<Form.Item name="expression" label="表达式">
  <Space.Compact>
    <Input placeholder="输入表达式" />
    <Button>配置</Button>
  </Space.Compact>
</Form.Item>
```

**正确做法**: 使用嵌套 Form.Item,外层负责 label 和 validation,内层使用 `noStyle` 负责 value 绑定:
```tsx
<Form.Item label="表达式" rules={[...]}>
  <Space.Compact style={{ width: '100%' }}>
    <Form.Item name="expression" noStyle>
      <Input placeholder="输入表达式" style={{ flex: 1 }} />
    </Form.Item>
    <Button>配置</Button>
  </Space.Compact>
</Form.Item>
```

**原则**: Form.Item 需要直接控制表单控件,中间不能有阻断 props 传递的包裹组件。

### 2. Ant Design 废弃属性替换

#### 2.1 Modal/Card 的 bodyStyle 属性

**废弃**: `bodyStyle` 属性已被废弃

**替换**:
```tsx
// ❌ 错误
<Modal bodyStyle={{ padding: 0 }}>

// ✅ 正确
<Modal styles={{ body: { padding: 0 } }}>

// ❌ 错误
<Card bodyStyle={{ padding: 12 }}>

// ✅ 正确
<Card styles={{ body: { padding: 12 } }}>
```

#### 2.2 Modal 的 destroyOnClose 属性

**废弃**: `destroyOnClose` 属性已被废弃

**替换**:
```tsx
// ❌ 错误
<Modal destroyOnClose>

// ✅ 正确
<Modal destroyOnHidden>
```

#### 2.3 Input 的 addonAfter 属性

**废弃**: `addonAfter` 属性已被废弃,建议使用 `Space.Compact`

**替换**: 参考上面的 Form.Item 嵌套方式

### 3. React Router 配置约束

**原则**:

- 路由初始化方式应与当前项目实际依赖版本保持一致,不要直接复制其他项目的 future flags、实验配置或迁移代码。
- 路由升级前先核对 `package.json` 中的实际版本,再决定是否启用兼容参数或迁移开关。
- 新增路由时优先延续当前 `src/router/index.tsx` 的集中声明方式,避免在多个入口文件中分散维护。

**检查点**:

- 路由入口是否与当前项目启动方式一致。
- 懒加载、嵌套路由和重定向是否沿用现有模式。
- 升级 Router 版本后是否同步完成构建与页面验证。

### 4. Ant Design message 静态函数使用

**问题**: 静态调用 `message.success()` 等方法无法使用动态主题上下文。

**建议**:

- 新代码优先通过 `App` 上下文提供的实例调用 message、notification、modal。
- 若历史代码仍存在静态调用,修改相关页面时应一并评估是否收口到上下文实例。
- 不要把“当前还能用”当成长期规范,避免继续扩散静态调用。

```tsx
// 1. 在应用根节点注入 Ant Design 的 App 组件
import { App as AntdApp } from 'antd'

function App() {
  return (
    <AntdApp>
      {/* 应用内容 */}
    </AntdApp>
  )
}

// 2. 在组件中使用 App 提供的 message 实例
import { App } from 'antd'

function MyComponent() {
  const { message } = App.useApp()

  const handleClick = () => {
    message.success('操作成功')
  }
}
```

### 5. 前端依赖版本兼容性

**原则**:

- 以前端 `package.json` 中声明的实际版本为准判断兼容性,不要沿用其他项目的版本结论。
- 升级 React、Ant Design、React Router、Vite 后,必须同步检查构建、类型、控制台警告和关键页面交互。
- 若某个依赖版本组合存在官方未完全覆盖的兼容性区间,应以当前项目真实验证结果记录处理结论,不要照搬旧项目说明。

### 6. 表格操作列实现规范

- 表格操作列默认使用纯图标按钮 + Tooltip，按钮风格使用 `type="text"`。
- 操作列应优先复用统一的共享组件或封装，禁止在业务页面手写一组风格各异的操作按钮。
- 纯图标按钮必须提供稳定语义标识，如 `aria-label` 或 `data-testid`，便于无障碍访问与自动化测试。
- 若某操作必须显示文字，必须先在需求或设计文档中声明例外原因，未经声明不得直接落地为文字按钮。
- 操作列按钮的 loading、danger、disabled、confirm 等状态，也应通过共享组件或约定统一收口，避免页面各自实现。

## 开发检查清单

在提交代码前,请检查以下事项:

- [ ] Form.Item 是否直接控制表单控件,没有被容器组件阻断
- [ ] 是否使用了废弃的 `bodyStyle` 属性 (应使用 `styles={{ body: {...} }}`)
- [ ] 是否使用了废弃的 `destroyOnClose` 属性 (应使用 `destroyOnHidden`)
- [ ] Modal/Drawer 等组件的样式属性是否使用了新的 API
- [ ] 表单值是否能正确显示和更新
- [ ] 控制台是否有 Ant Design 的废弃警告
- [ ] 表格操作列是否复用了统一操作按钮组件,没有直接手写文字按钮
- [ ] 纯图标按钮是否提供了稳定的 `aria-label` 或等价语义标识

## 构建验证

修改前端代码后,务必执行构建验证。具体命令按项目特有附录执行。

确保:
1. 构建成功,无 TypeScript 类型错误
2. 控制台无新增废弃警告或版本兼容警告
3. 关键功能页面交互通过验证
