## 7. 回退方案

### 7.1 回退触发条件

| 条件 | 处理 |
| --- | --- |
| 应用无法启动 | 立即停止新实例，回退到上一版 JAR / 前端静态包 |
| 健康检查失败 | 停止流量切换，恢复旧版本 |
| 统一查询主链路失败 | 恢复旧版本并保留问题现场日志 |
| 管理端页面无法加载或前后端代理失效 | 回退前端静态包，必要时同时回退后端 |

### 7.2 回退步骤

| 步骤 | 操作 |
| --- | --- |
| 1 | 停止当前发布实例 |
| 2 | 恢复上一版后端 JAR |
| 3 | 恢复上一版前端静态产物 |
| 4 | 重新启动后端与前端发布实例 |
| 5 | 复核 `GET /actuator/health` 与 `GET /api/platform/baseline` |
| 6 | 使用 `query_debug_demo_v2` 做最小查询冒烟 |

### 7.3 数据回退原则

| 项目 | 原则 |
| --- | --- |
| Flyway 已执行但业务异常 | 不直接手工改表，优先按新版本补救迁移或恢复数据库备份 |
| 元数据变更 | 发布准备阶段只补发布所需固定演示数据；若误配，可删除对应服务元数据并重新导入 |
| 演示服务 | `query_debug_demo_v2` 作为发布后冒烟基线，默认保留，不作为回退删除对象 |
