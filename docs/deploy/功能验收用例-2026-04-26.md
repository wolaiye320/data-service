| 用例编号 | 验收主题 | 前置条件 | 执行步骤 | 预期结果 |

| F-02 | MySQL 连接管理 | 已具备 `MYSQL_USER` / `MYSQL_PASSWORD`；`mysql_federation1.fed_test_order` 可读 | 1. 在 `/connections` 新增 MySQL 连接。2. 执行测试连接。3. 查看列表状态。 | MySQL 连接保存成功；测试连接成功；列表可见 MySQL 连接并处于启用状态。 |
| F-03 | Oracle 连接管理 | `ds-oracle-xe-check` 运行；`ORACLE_TEST.orders` 可读 | 1. 在 `/connections` 新增 Oracle 连接。2. 执行测试连接。 | Oracle 连接保存成功；测试连接成功；无明文凭据回显。 |
| F-04 | SQL-first 草稿保存与快照解析 | 已有 PostgreSQL 连接 | 1. 进入 `/services`。2. 新增简单 SQL 服务：`select id, order_name from public.orders where id = /* orderId */1`。3. 保存草稿。4. 打开编辑抽屉查看来源、参数、字段快照。 | 服务处于草稿态；来源快照包含 `public.orders`；参数快照包含 `orderId/LONG`；字段快照包含 `id`、`order_name`。 |
| F-05 | 服务发布、停用与版本快照 | 已完成 F-04 | 1. 发布草稿服务。2. 验证当前版本号为 `1`。3. 停用服务。 | 服务从草稿态变为已发布态，再可切换为已停用态；版本快照可追溯；停用后服务不可对外调用。 |
| F-06 | SQL 预览执行与诊断 | 已完成 F-04；服务保持草稿或重新编辑草稿 | 1. 在服务编辑抽屉输入 `previewParams={"orderId":1}`。2. 执行预览。3. 查看结果区与诊断摘要。 | 返回 `order-a`；显示耗时、返回行数、连接编码等诊断字段；预览不产生正式发布版本。 |
| F-07 | 统一查询 API 单源调用 | 已发布 PostgreSQL 单源服务 | 1. 调用 `/api/data-services/query`。2. 传入 `orderId=1`、`callerId`。 | 返回统一结构；`status=SUCCESS`；结果为 `order-a`；包含 `serviceVersion`、`traceId`、`elapsedMs`。 |
| F-08 | 同构联邦查询 | 已存在 `public.orders`、`public.order_items` 样本 | 1. 创建联邦 SQL：`PG_MAIN@public.orders` Join `PG_ARCHIVE@public.order_items`。2. 保存、发布并调用。 | 保存与发布成功；返回 `order_id=1, item_sku=sku-a`；能查看执行计划或诊断摘要。 |
| F-09 | 异构联邦查询 | 已存在 `postg_federation1.fed_test_customer` 与 `mysql_federation1.fed_test_order` | 1. 创建联邦 SQL：按 `customer_code` 关联 PostgreSQL 客户表与 MySQL 订单表。2. 保存、发布并调用 `C1001`。 | 返回 `Alice Zhang` 对应的 2 条订单；调用方无需感知底层数据库差异；诊断中能看见联邦阶段信息。 |
| F-10 | 复杂表达式与方言适配 | PostgreSQL、MySQL、Oracle 样本可读 | 1. 创建包含 `concat`、`case when amount >= 1000`、`count(*)` 等表达式的服务。2. 保存或发布。 | 支持范围内表达式能成功保存 / 发布 / 查询；不支持表达式明确失败；返回字段别名完整。 |
| F-11 | 批量查询成功与部分失败 | 已发布单源服务；批量输入按 `14.2.2` 准备 | 1. 用 `orderId=1,2` 做批量成功查询。2. 用 `orderId=1,'bad'` 做部分失败查询。 | 成功场景中结果与输入顺序一一对应；失败场景中仅错误项失败，返回稳定错误结构与 `successCount/failureCount`。 |
| F-12 | 缓存命中、隔离与失效 | 已发布单源服务；已配置缓存策略 | 1. 首次查询 `orderId=1`。2. 重复查询同参数。3. 更换 `callerId` 且开启 `contextKeys=['callerId']`。4. 发布新版本或清理缓存后再次查询。 | 第二次查询命中缓存；不同调用上下文不复用缓存；版本变化、策略变化、显式清理后缓存按预期失效。 |
| F-13 | 权限控制与租户上下文 | 已发布租户限定服务；已知 `tenant-a/tenant-b` | 1. 省略管理员头访问管理接口。2. 省略 `callerId` 调用统一查询。3. 用 `tenant-b` 调用 `tenant-a` 服务。 | 三类未授权访问都被明确拒绝；错误结构稳定；租户越权场景不会返回业务数据。 |
| F-14 | 审计检索 | 已执行 F-01、F-05、F-06、F-13 生成审计日志 | 1. 进入 `/audits`。2. 按 `serviceCode`、`eventType`、`traceId` 检索。3. 打开详情抽屉。 | 可检索保存、发布、停用、测试连接、预览、查询、权限失败等审计；详情包含摘要、详情 JSON、上下文摘要。 |
| F-15 | 前端 SQL-first 自助配置闭环 | 前端与后端可用 | 1. 在 `/services` 完成新增、保存、发布、预览。2. 在 `/audits` 查看记录。 | 管理员可只通过前端完成 SQL-first 服务配置、发布与审计查看，不需要改代码。 |
